1. The Basic Steps for Writing Your Own Function in Python

1. What is a Function?

We have actually been using functions since we started learning Python.

But most of the ones we used are Python's built-in functions.

For example, print(), which shows up in almost every chapter.

Now we will mainly learn how to write our own functions.

Have you ever wondered why we need functions?

To answer that, we first need to know what a function is.

A function is a block of organised, reusable code that does one job (or a few related jobs).

That's right – a function is just a piece of code we've pulled out and given a name.

So why pull it out?

To make it easy to use, and easy to use again and again.

At heart, a function works like this: we feed some data into it, it "digests" it inside, and then it gives back what we want. How it digests the data – we don't need to know. It handles that inside.

What does this mean?

Take the print function we use all the time. We know its job is to show our data in the console so we can see it. So with print('Brother Shui'), we want to show Brother Shui. We feed the data Brother Shui into the print function, and it prints the result in the console for us.

2. How to Define Your Own Function

How do you define your own function?

To know how to define one, you need to know what parts a function has:

Python· Syntax only
def function_name(parameter1, parameter2....parameterN):
    function body
    return statement

These are the parts of a Python function.

So to define your own function, follow these rules:

  • A function starts with the keyword def, then the function's name and round brackets ().
  • Any parameters (inputs) go inside the brackets. The brackets are where you define parameters.
  • The first line of the function can be a docstring (a description of the function). This is optional.
  • The function's body starts after a colon, and is indented.
  • return [expression] ends the function and can send a value back to the caller. A return with no expression gives back None.

Syntax:

Python· Read with the text above
def functionname( parameters ):
   "function_docstring"
   function_suite
   return [expression]

Example:

  1. Use def to define a function called sum
  2. Give it two parameters, num1 and num2
  3. The first line of the function describes it: the sum of two numbers
  4. Finally, the return statement ends the function and gives back the sum of the two numbers
Python· Runs on this page
def sum(num1,num2):
	"Sum of two numbers"
	return num1+num2

# Call the function
print(sum(5,6))

Output:

Python· Read with the text above
11

    2. Return Values
    

    From what we've learned, the return [expression] statement exits a function and can send a value back to the caller.
    

    A return statement with no value returns None.
    

    Here's an example:
    

    Python· Runs on this page
    # -*- coding: UTF-8 -*-

def sum(num1,num2):
	# Sum of two numbers
	if not (isinstance (num1,(int ,float)) and isinstance (num2,(int ,float))):
		raise TypeError('Wrong argument type')
	return num1+num2

print(sum(1,2))
    

    Result:
    

    Text
    3
    

    This example also uses the built-in function isinstance() to check data types. It checks whether the arguments are integers or floats. If not, it raises an error with the message Wrong argument type, like this:
    

    Python· Read with the text above
    # -*- coding: UTF-8 -*-

def sum(num1,num2):
	# Sum of two numbers

    A function can also return several values. Here's an example:
    

    Python· Runs on this page
    # -*- coding: UTF-8 -*-

def  division ( num1, num2 ):
	# Find the quotient and the remainder
         a = num1 % num2
         b = (num1-a) / num2
         return b , a

num1 , num2 = division(9,4)
tuple1 = division(9,4)

print (num1,num2)
print (tuple1)

    Look closely. The first output makes it look like several values were returned. But actually, Python first made a tuple, and then returned that.
    

    Remember: you can make a tuple just by using commas. Look at the return in the example – we're really using commas to make a tuple.
    

    In Python, a function can return several values, which many other languages can't do. This is one way Python is simpler and more flexible than other languages.
    

    When Python returns several values at once, the data type is a tuple.

      3. Function Parameters
      

      1. Kinds of Parameters
      

      Setting up and passing parameters is the key part of functions, and Python is very flexible about parameters.
      

      The main kinds are: default parameters, keyword arguments, and variable-length parameters.
      

      Let's look at them one by one.
      

      2. Default Parameters
      

      Sometimes, when someone calls our function without giving a certain argument, we want to use a default value. That's what default parameters are for.
      

      To make a default parameter, just give the parameter a value when you define the function.
      

      For example:
      

      Python· Runs on this page
      # -*- coding: UTF-8 -*-

def print_user_info( name , age , sex = 'Male' ):
    # Print the user's info
    print(f'Nickname: {name}' , end = ' ')
    print(f'Age: {age}' , end = ' ')
    print(f'Sex: {sex}')
    return;

# Call the print_user_info function

print_user_info( 'Two Drops' , 18 , 'Female')
print_user_info( 'Three Drops' , 25 )
      

      Output:
      

      Text
      Nickname: Two Drops Age: 18 Sex: Female
Nickname: Three Drops Age: 25 Sex: Male
      

      From the output, you can see that when a parameter has a default value, and you don't pass that argument, the default is used.
      

      But be careful: only the parameters at the end of the list can have default values. You can't put a parameter with a default value before one without a default.
      

      This is because values are given to parameters by position. For example, def func(a, b=1) is valid, but def func(a=1, b) is not. 
      

      Is that everything about default parameters?
      

      Not yet! Think about it: if the parameter is a changeable container, like a list or a dict, what should we use as the default?
      

      We can use None as the default, like this:
      

      Python· Read with the text above
      # If b is a list, you can use None as the default
def print_info( a , b = None ):
    if b is None :
        b=[]
    return;
      

      Looking at this, you might wonder: why not just write b=[] in the parameters?
      

      Like this:
      

      Python· Read with the text above
      def print_info( a , b = [] ):
    return;
      

      Is that OK?
      

      It runs without errors. So can we write it like this?
      

      Pay special attention here: default values should be immutable objects, like None, True, False, numbers or strings. If you do what's shown above, you'll run into all kinds of trouble when the default value gets changed somewhere else.
      

      Those changes will affect the default value the next time you call the function.
      

      Here's an example:
      

      Python· Runs on this page
      # -*- coding: UTF-8 -*-

def print_info( a , b = [] ):
    print(b)
    return b ;

result = print_info(1)

result.append('error')

print_info(2)
      

      Output:
      

      Text
      []
['error']
      

      Look carefully: the second output is not what you wanted at all. So never do this.
      

      One more thing: sometimes I don't want a default value at all. I just want to check whether the caller passed something or not. How do I do that?
      

      We can do this:
      

      Python· Read with the text above
      _no_value =object()

def print_info( a , b = _no_value ):
    if b is _no_value :
        print('b was not given a value')
    return;
      

      object is the base class of all classes in Python. You can make an instance of object, but it's not really useful for anything – it has no useful methods and no instance data (it has no instance dictionary, so you can't even set attributes on it). The only thing you can do with it is test whether something is that exact object. We use exactly this feature to check whether a value was passed in.
      

      3. Keyword Arguments
      

      Usually when we pass arguments to a function, we have to pass them in order. If the order is wrong, the wrong values go to the wrong parameters.
      

      But in Python, you can pass arguments by name, without worrying about the order in the definition. These are called keyword arguments.
      

      Keyword arguments have two advantages:
      

        

      • 

        We don't have to worry about the order, so functions are easier to use.
        

        • 

      • 

        If the other parameters have default values, we only need to give values for the ones we want.
        

        • 

      

      Here's an example:
      

      Python· Runs on this page
      # -*- coding: UTF-8 -*-

def print_user_info( name ,  age  , sex = 'Male' ):
    # Print the user's info
    print(f'Nickname: {name}' , end = ' ')
    print(f'Age: {age}' , end = ' ')
    print(f'Sex: {sex}')
    return;

# Call the print_user_info function

print_user_info( name = 'Two Drops' ,age = 18 , sex = 'Female')
print_user_info( name = 'Two Drops' ,sex = 'Female', age = 18 )
      

      Output:
      

      Text
      Nickname: Two Drops Age: 18 Sex: Female
Nickname: Two Drops Age: 18 Sex: Female
      

      4. Variable-Length Parameters
      

      Sometimes when we design a function, we don't know how many arguments will be passed in.
      

      Then we can use variable-length parameters.
      

      Python lets you collect extra arguments into a tuple. You do this by putting a star * before the parameter.
      

      If no extra arguments are given when calling, it's just an empty tuple. So you don't have to pass any extra unnamed values.
      

      For example:
      

      Python· Runs on this page
      # -*- coding: UTF-8 -*-

def print_user_info( name ,  age  , sex = 'Male' , * hobby):
    # Print the user's info
    print(f'Nickname: {name}' , end = ' ')
    print(f'Age: {age}' , end = ' ')
    print(f'Sex: {sex}' ,end = ' ' )
    print(f'Hobbies: {hobby}')
    return;

# Call the print_user_info function
print_user_info( 'Two Drops' ,18 , 'Female', 'basketball','badminton','running')
      

      Output:
      

      Python· Output
      Nickname: Two Drops Age: 18 Sex: Female Hobbies: ('basketball', 'badminton', 'running')
      

      From the output, you can see that *hobby is a variable-length parameter, and hobby is actually a tuple.
      

      Variable-length parameters also work with keyword arguments. Extra keyword arguments that weren't defined are put into a dictionary.
      

      You do this by putting ** before the parameter. Let's change the example above:
      

      Python· Read with the text above
      # -*- coding: UTF-8 -*-

def print_user_info( name ,  age  , sex = 'Male' , ** hobby ):
    # Print the user's info
    print(f'Nickname: {name}' , end = ' ')
    print(f'Age: {age}' , end = ' ')
    print(f'Sex: {sex}' ,end = ' ' )
    print(f'Hobbies: {hobby}')
    return;

# Call the print_user_info function
print_user_info( name = 'Two Drops' , age = 18 , sex = 'Female', hobby = ('basketball','badminton','running'))
      

      Output:
      

      Text
      Nickname: Two Drops Age: 18 Sex: Female Hobbies: {'hobby': ('basketball', 'badminton', 'running')}	
      

      Comparing the two examples: *hobby is a variable-length parameter, and hobby is a tuple. **hobby collects keyword arguments, and hobby is a dict.
      

      5. Keyword-Only Parameters
      

      Keyword arguments are easy to use and help prevent mistakes. So sometimes, we want our function to force some arguments to be passed by keyword. How do we do that?
      

      Put those parameters after a * parameter, or after a single * on its own. For example:
      

      Python· Runs on this page
      # -*- coding: UTF-8 -*-

def print_user_info( name , *, age  , sex = 'Male' ):
    # Print the user's info
    print(f'Nickname: {name}' , end = ' ')
    print(f'Age: {age}' , end = ' ')
    print(f'Sex: {sex}')
    return;

# Call the print_user_info function
print_user_info( name = 'Two Drops' ,age = 18 , sex = 'Female' )

# This would give an error, because age and sex must be passed as keyword arguments
#print_user_info( 'Two Drops' , 18 , 'Female' )
print_user_info('Two Drops',age='22',sex='Male')
      

      From the example, if age and sex are not passed as keyword arguments, you get an error.
      

      In many cases, keyword-only arguments make the meaning clearer than positional ones, and the program is easier to read. They are also better than using **kw, and they're useful in more advanced situations too.
      

      6. Python 3.10+ Type Hints
      

      Hey everyone! After seeing all these kinds of parameters, have you noticed a problem? Just by looking at a function's name and parameter list, we don't actually know what type each parameter should be.
      

      For example, in the function below, can you tell at a glance that name is a string and age is an integer?
      

      Python· Read with the text above
      def print_user_info(name, age, sex='Male'):
    print(f'Nickname: {name} Age: {age} Sex: {sex}')
      

      Someone calling it could easily pass the wrong type – even passing a list won't give an error straight away. The problem only shows up halfway through running. This is when type hints are useful.
      

      Let's look at the basic form first:
      

      Python· Runs on this page
      def print_user_info(name: str, age: int, sex: str = 'Male') -> None:
    print(f'Nickname: {name} Age: {age} Sex: {sex}')


print_user_info('Two Drops', 18, 'Female')
      

      Output:
      

      Text
      Nickname: Two Drops Age: 18 Sex: Female
      

      The : str and : int after the parameters, and the arrow -> None, are type hints. Note: when Python runs, it does not force these hints – if you pass a list anyway, you won't get an error right away. Type hints are really for people: you, your teammates, and tools like IDEs, mypy and pyright (static checkers). They make code easier to read and maintain.
      

      What if a value might be None?
      

      Before Python 3.10, you wrote Optional[str]:
      

      Python· Runs on this page
      from typing import Optional


def find_user(name: str) -> Optional[str]:
    # Return None if not found
    if name == 'Two Drops':
        return '131456780002'
    return None


print(find_user('Two Drops'))
print(find_user('Six Drops'))
      

      Output:
      

      Text
      131456780002
None
      

      Nothing wrong with that, but you have to import something extra, which is a bit wordy. From Python 3.10, you can just use | to mean "or" (PEP 604):
      

      Python· Runs on this page
      def find_user(name: str) -> str | None:
    if name == 'Two Drops':
        return '131456780002'
    return None


print(find_user('Two Drops'))
print(find_user('Six Drops'))
      

      Output:
      

      Text
      131456780002
None
      

      Much cleaner, right? str | None reads as "a string or None". No need for the name Optional.
      

      What about container types like list and dict?
      

      Before Python 3.9, you had to import capitalised List and Dict from typing:
      

      Python· Runs on this page
      from typing import List, Dict


def get_users() -> List[str]:
    return ['One Drop', 'Two Drops', 'Three Drops']


def get_phones() -> Dict[str, str]:
    return {'Two Drops': '131456780002'}


print(get_users())
print(get_phones())
      

      From Python 3.9 (PEP 585), you can use the built-in lowercase list and dict directly as type hints:
      

      Python· Runs on this page
      def get_users() -> list[str]:
    return ['One Drop', 'Two Drops', 'Three Drops']


def get_phones() -> dict[str, str]:
    return {'Two Drops': '131456780002'}


print(get_users())
print(get_phones())
      

      Both give the same output:
      

      Text
      ['One Drop', 'Two Drops', 'Three Drops']
{'Two Drops': '131456780002'}
      

      Now you don't even need from typing import .... Even simpler.
      

      Type hints can also be used in classes. A common case is with dataclass:
      

      Python· Runs on this page
      from dataclasses import dataclass


@dataclass
class User:
    name: str
    age: int
    sex: str = 'Male'


u = User('Two Drops', 18, 'Female')
print(u)
      

      Output:
      

      Text
      User(name='Two Drops', age=18, sex='Female')
      

      dataclass is really handy. We'll talk about it more when we cover object-oriented programming later.
      

      

      Python 3.12+: the type keyword for type aliases
      

      

      Finally, one more new thing from Python 3.12 (PEP 695). If you have a really long type that you keep writing again and again, you can use the type keyword to give it a short name (an alias):
      

      Python· Read with the text above
      type UserId = int | str
type PhoneBook = dict[str, str]


def find_phone(book: PhoneBook, name: str) -> str | None:
    return book.get(name)


book: PhoneBook = {'Two Drops': '131456780002'}
print(find_phone(book, 'Two Drops'))
      

      Output:
      

      Text
      131456780002
      

      Here UserId and PhoneBook are type aliases. They look like variable assignments, but they mean "this is a type".
      

      There's a lot more to type hints – generics, Protocols, TypeVar and other advanced things. We'll have a whole chapter on them later in this book. For now, the most common ones above are enough for everyday coding.

          4. How Values Are Passed to Functions
          

          Let's start with an example:
          

          Python· Runs on this page
          # -*- coding: UTF-8 -*-
def chagne_number( b ):
    b = 1000

b = 1
chagne_number(b)
print( b )
          

          The output is:
          

          Text
          1
          

          Did you see the result?
          

          Think about it: why does it print 1 and not 1000?
          

          The real question is: why didn't the function chagne_number change the value of b?
          

          Lots of programming languages talk about this, and the explanation is similar.
          

          When you pass arguments to a function, you pass objects. We learned about Python's basic data types before. These objects can be split into changeable (mutable) types and unchangeable (immutable) types.
          

          In Python, strings, integers, floats and tuples are immutable. Lists, dicts and so on are mutable.
          

          For example:
          

          Immutable types: when you write a = 1, Python makes an integer object 1, and variable a points to it. When you then write a = 1000, Python makes a new integer object 1000 and changes where a points. a no longer points to 1, it points to 1000, and the 1 is thrown away.
          

          Mutable types: when you write a = [1,2,3,4,5,6], Python makes a list object with 6 elements, and a points to the list. a[2] = 5 changes the third element inside list a. This is different from above: a doesn't point somewhere new – the element inside the list is changed directly.
          

          Immutable type (the variable points somewhere new):
          

          

          Mutable type (the elements inside the object are changed directly):
          

          

          This also affects how arguments are passed to functions:
          

          Immutable types: similar to "pass by value" in C++. Examples: integers, strings, tuples. With fun(a), only the value of a is passed, and object a itself isn't affected. If you change a inside fun(a), you're working on another object, and the original a doesn't change.
          

          Mutable types: similar to "pass by reference" in C++. Examples: lists, dictionaries. With fun(a), the real a is passed in, so if it's changed inside, the a outside fun is changed too.
          

          So in the first example, b = 1 creates an integer object 1, and b points to it. When it's passed to chagne_number, only the value of b is passed, and b itself isn't affected. Look at this changed version – the printed results make it easier to understand:
          

          Python· Runs on this page
          # -*- coding: UTF-8 -*-
def chagne_number( b ):
    print(f'b at the start of the function: {b}')
    b = 1000
    print(f'b after assigning in the function: {b}')


b = 1
chagne_number( b )
print(f'b at the end: {b}')
          

          Output:
          

          Text
          b at the start of the function: 1
b after assigning in the function: 1000
b at the end: 1
          

          Of course, if the argument is a mutable type, then after calling the function, the original value will be changed. Here's an example:
          

          Python· Runs on this page
          # -*- coding: UTF-8 -*-

def chagne_list( b ):
    print(f'b at the start of the function: {b}')
    b.append(1000)
    print(f'b after changing in the function: {b}')


b = [1,2,3,4,5]
chagne_list( b )
print(f'b at the end: {b}')
          

          Output:
          

          Text
          b at the start of the function: [1, 2, 3, 4, 5]
b after changing in the function: [1, 2, 3, 4, 5, 1000]
b at the end: [1, 2, 3, 4, 5, 1000]
          

          Both are lists – why does one change and the other not?
          

          Don't read ahead yet! Let's try another question: if you pass in a list, and then reassign the parameter inside the function, will the list outside definitely change?
          

          First guess what the two prints show, then run the code:
          

          Python· Runs on this page
          def replace_items(items):
    items = [1000]


def append_item(items):
    items.append(1000)


numbers = [1, 2]
replace_items(numbers)
print(numbers)
append_item(numbers)
print(numbers)
          

          Output:
          

          Text
          [1, 2]
[1, 2, 1000]
          

          See? We passed in the same list both times, but the results are different.
          

          The reason goes back to what variables point to. When the function is called, the parameter name items and the outside name numbers point to the same list. items = [1000] makes the items inside the function point to a different list – the outside numbers doesn't change. items.append(1000) doesn't change where anything points. It adds an element into the original list, so the outside sees the change too.
          

          When you think about the "pass by value / pass by reference" comparison above, keep one limit in mind: Python doesn't switch to a different passing method depending on whether an object can change, and it doesn't copy an integer when you pass it in. The parameter name is simply bound to the object passed in. What makes the difference here is whether the code rebinds the name or changes the object. You can read the official Python FAQ to understand it better.
          

          Now change it yourself: if numbers starts as an empty list, what should the two prints show? Write your answer first, then run it. You should get [] and then [1000], for the same reason.
          

          Why does a default list remember the last call?
          

          In the parameters section, we said to be careful using a list as a default value. This isn't because Python's syntax forbids it. It's because the default value is created once, when the function is defined, and every later call that leaves out that argument shares it.
          

          Let's try it with our little "record study time" task:
          

          Python· Runs on this page
          def record_minutes(minutes, records=[]):
    records.append(minutes)
    return records


print(record_minutes(5))
print(record_minutes(10))
          

          Output:
          

          Text
          [5]
[5, 10]
          

          If we want a new record list for every call, then seeing 5 again in the second result isn't what we expected. We can write it like this instead:
          

          Python· Runs on this page
          def record_minutes(minutes, records=None):
    if records is None:
        records = []
    records.append(minutes)
    return records


print(record_minutes(5))
print(record_minutes(10))
          

          Output:
          

          Text
          [5]
[10]
          

          Here None means "the caller didn't give a record list", so the function makes a new one itself. If the caller does pass in the same list each time, the records will still add up. Try it yourself: create records = [], call record_minutes(5, records) and record_minutes(10, records), then print records. You should get [5, 10]. This time, sharing is something we chose on purpose.
          

          When you read the official tutorial on default argument values, look for the answer to one question: when exactly is the default value created? Find that first, then come back and explain the two outputs above.
          

          It printed something – so why did I get None?
          

          Finally, let's separate two things that often get mixed up. A function printing a result on the screen and a function returning a result to the caller are two different things.
          

          Python· Runs on this page
          def show_minutes(minutes):
    print(minutes)


def get_minutes(minutes):
    return minutes


shown = show_minutes(15)
saved = get_minutes(15)
print(shown)
print(saved)
          

          Output:
          

          Text
          15
None
15
          

          The first line is printed by show_minutes itself. It has no return, so shown gets None. get_minutes returns 15 to the caller, and the outside print(saved) prints it.
          

          Now write your own total_minutes(first, second): it should return the total of two study times, and not print anything inside the function. Test it with total_minutes(5, 10), total_minutes(0, 0) and total_minutes(12, 3). The results should be 15, 0 and 15. If you can explain the difference between printing and returning, and complete these three calls on your own, then you've really got this part.

          5. Anonymous Functions
          

          Have you ever wanted to define a very short callback function, without writing a whole function using def? Is there a shortcut?
          

          Yes, there is!
          

          Python uses lambda to create anonymous functions – functions defined without the normal def statement.
          

          Anonymous functions have these features:
          

            

          • A lambda is just an expression. Its body is much simpler than a def function.
            • 

          • The body of a lambda is one expression, not a block of code. You can only put a little bit of logic inside it.
            • 

          • A lambda has its own namespace, and can't access variables outside its own parameter list or the global namespace.
            • 

          

          Basic syntax
          

          Python· Syntax only
          lambda [arg1 [,arg2,.....argn]]:expression
          

          Example:
          

          Python· Runs on this page
          # -*- coding: UTF-8 -*-

sum = lambda num1 , num2 : num1 + num2;

print( sum( 1 , 2 ) )
          

          Output:
          

          Text
          3
          

          Note: although a lambda lets you define a simple function, there are limits. You can only write a single expression, and its value is what gets returned. That means you can't use other language features, like multiple statements, loops or exception handling.
          

          There's one thing you must watch out for with anonymous functions. Let's change the example above:
          

          Python· Runs on this page
          # -*- coding: UTF-8 -*-

num2 = 100
sum1 = lambda num1 : num1 + num2 ;

num2 = 10000
sum2 = lambda num1 : num1 + num2 ;

print( sum1( 1 ) )
print( sum2( 1 ) )
          

          What do you think it prints? You might expect 101 first and 10001 second. But no – the output is:
          

          Text
          10001
10001
          

          This is because num2 in the lambda is a free variable. Its value is looked up when the lambda RUNS, not when it's DEFINED. This is different from how default parameter values work. So in a case like this, it's better to use the first way (default parameters).
