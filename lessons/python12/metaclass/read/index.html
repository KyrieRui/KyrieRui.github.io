1. In Python, Classes Are Objects Too

Before we learn about metaclasses, let's understand Python classes a bit more deeply. In most programming languages, a class is a piece of code that describes how to make an object. That's true in Python too.

We stressed this in the chapter on classes. Let's remind ourselves with an example:

Python· Read with the text above
class ObjectCreator(object):
    pass


mObject = ObjectCreator()
print(mObject)

Output:

Text
<__main__.ObjectCreator object at 0x00000000023EE048>

But Python classes are different from most languages in one way: in Python, a class is also an object. Yes, that's not a typo – it's an object.

Why?

Because whenever you use the keyword class, the Python interpreter creates an object when it runs.

For example:

Python· Read with the text above
class ObjectCreator(object):
    pass

When the program runs this code, it creates an object in memory called ObjectCreator. This object (the class) itself has the ability to create objects (instances of the class) – and that's what makes it a class.

But underneath, it's still an object. So we can do these things with it:

Python· Read with the text above
class ObjectCreator(object):
    pass


def echo(ob):
    print(ob)


mObject = ObjectCreator()
print(mObject)

# You can print a class directly, because it's actually an object too
print(ObjectCreator)
# You can pass a class to a function as an argument (note: the class itself, not an instance)
echo(ObjectCreator)
# You can also assign a class to a variable
objectCreator = ObjectCreator
print(objectCreator)

Output:

Text
<__main__.ObjectCreator object at 0x000000000240E358>
<class '__main__.ObjectCreator'>
<class '__main__.ObjectCreator'>
<class '__main__.ObjectCreator'>

2. Using type() to Create Classes on the Fly

Because classes are objects, we can create classes while the program is running.

Python is a dynamic language.

The biggest difference between dynamic and static languages is that functions and classes aren't defined when the code is compiled – they're created dynamically while the program runs.

First, let's get to know the type() function.

Create a module called hello.py, and define a class called Hello:

Python· Read with the text above
class Hello(object):
    def hello(self, name='Py'):
        print('Hello,', name)

Then, in another module, import the hello module and print some information.

The type() function lets you see the type of a class or a variable.

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

from com.twowater.hello import Hello

h = Hello()
h.hello()

print(type(Hello))
print(type(h))

What will the output be?

Text
Hello, Py
<class 'type'>
<class 'com.twowater.hello.Hello'>

As we said, type() shows the type of a class or variable. Hello is a class, and its type is type. h is an instance, and its type is com.twowater.hello.Hello.

The com.twowater part at the front is my package name; the hello module lives in that package.

Let's think about this a bit more. In the example above, we used type() to see the type of something.

When we looked at the type of the Hello class, it printed <class 'type'>.

In fact, type() can not only return the type of an object – it can also create new types.

Classes are created dynamically at runtime, and the way to create a class is with the type() function.

For example, we can use type() to create the Hello class from above. Look at this code:

Python· Runs on this page
Practise on the challenge page →
# -*- coding: UTF-8 -*-

def printHello(self, name='Py'):
    # A function that prints Hello
    print('Hello,', name)


# Create a Hello class
Hello = type('Hello', (object,), dict(hello=printHello))

# Create an instance of Hello
h = Hello()
# Call the Hello class's method
h.hello()
# Look at the type of the Hello class
print(type(Hello))
# Look at the type of instance h
print(type(h))

Output:

Text
Hello, Py
<class 'type'>
<class '__main__.Hello'>

Here's what the arguments mean when you create a class with type():

  1. The name of the class – in the example, Hello

  2. A tuple of parent classes. Python supports multiple inheritance. If there's only one parent, use the one-element tuple form. In the example, it inherits from object, so it's written (object,)

  3. A dictionary linking method names to functions. In the example, the function printHello is linked to the method name hello

The general pattern is:

Python· Syntax only
type(class_name, tuple_of_parent_classes (can be empty), dict_of_attributes (names and values))

Now that we understand the arguments, look at the output: a class made with type() is exactly the same as one written with class.

This is because when the Python interpreter sees a class definition, it just reads the syntax, and then calls type() to create the class.

Normally, we define classes with class ***..., but type() can create classes too.

This means a dynamic language can create classes while running. This is very different from static languages. To create a class while a static language program is running, you'd have to build a string of source code and call the compiler, or use tools to generate bytecode. That's basically dynamic compiling, and it's very complicated.

So you can see: in Python, classes are objects too, and you can create classes dynamically.

This is actually what Python does behind the scenes when you use the class keyword – and it does it using metaclasses.

3. What is a Metaclass?

After all that, we've finally (sort of) arrived at metaclasses. But we still don't know what on earth a metaclass is.

When we create a class, it's usually so we can create instances (objects) of it.

So what's a metaclass for?

A metaclass is used to create classes. Another way to think about it: a metaclass is the class of a class.

From the type() introduction above, we know we can create a class with type():

Python· Read with the text above
MyClass = type('MyClass', (), {})

In fact, type is a metaclass.

type is the metaclass Python uses behind the scenes to create all classes.

Now we can guess why it's type and not Type.

Probably to match str – str is the class that creates string objects, and int is the class that creates integer objects.

type is the class that creates class objects.

You can see this by checking the __class__ attribute.

Everything in Python – yes, everything – is an object.

That includes integers, strings, functions and classes. They're all objects, and they're all created from a class.

Python· Runs on this page
Practise on the challenge page →
# Integer
age = 23
print(age.__class__)
# String
name = 'Two Drops'
print(name.__class__)


# Function
def fu():
    pass


print(fu.__class__)


# Instance
class eat(object):
    pass


mEat = eat()

print(mEat.__class__)

Output:

Text
<class 'int'>
<class 'str'>
<class 'function'>
<class '__main__.eat'>

You can see that all of these – all objects – were created by a class. So you might wonder: what's the __class__ of the __class__?

In other words, what's the class that creates these classes?

Let's add this code to the code above:

Python· Read with the text above
print(age.__class__.__class__)
print(name.__class__.__class__)
print(fu.__class__.__class__)
print(mEat.__class__.__class__)

Output:

Text
<class 'type'>
<class 'type'>
<class 'type'>
<class 'type'>

Look carefully and think it through. The output above is the __class__ of the __class__ of the integer age, the string name, the function fu and the instance mEat.

You could also say it's the class of their class. And every one printed type.

As we said at the start, a metaclass is the class of a class.

So a metaclass is something that creates classes.

You can also think of it as: a metaclass is what makes classes.

And type is the built-in metaclass – the metaclass that comes with Python.

First tell objects and classes apart, then look at the tool that makes classes

This chapter can get confusing, because we're not just creating instances – we're talking about classes themselves. Let's use three checks to lay out the relationships:

Python· Runs on this page
Practise on the challenge page →
StudyRecord = type('StudyRecord', (), {'category': 'Study record'})
record = StudyRecord()
print(type(record) is StudyRecord)
print(type(StudyRecord) is type)
print(record.category)

Output:

Text
True
True
Study record

The first line creates a class, and the second line uses that class to create an instance. type(record) checks what class the instance belongs to, and type(StudyRecord) goes one step further and checks the type of the class itself. In this normal example, the class was created by type.

Now write the matching version yourself using class StudyRecord:, give it the same category, and compare these three results. First understand how the two ways of creating a class line up, then come back and look at what a custom metaclass does during creation.

Metaclasses are an advanced topic. If you don't need them yet the first time through, finish the comparison above and carry on with the later lessons. Come back with the question "what else can happen when a class is created?" They are not needed for normal functions, scripts or the final project.

4. Writing Your Own Metaclass

By now, we know what on earth a metaclass is.

But we still don't know what a metaclass is actually for.

We've only got to know it a little.

Before we learn what it's for, let's learn how to write our own metaclass.

Because only once you know how to write one can you really understand what it does.

First, let's look at the __metaclass__ attribute.

"Metaclass" literally means "class beyond a class". Simply put:

Once we define a class, we can create instances from it. So: first define a class, then create instances.

But what if we want to create classes?

Then we must create the class from a metaclass. So: first define a metaclass, then create classes.

Putting it together: first define a metaclass, then you can create classes, and finally create instances.

So a metaclass lets you create classes or change classes.

In other words, you can think of a class as an "instance" created by a metaclass.

Python· Syntax only
class MyObject(object):
    __metaclass__ = something…
[…]

If you write this, Python will use the metaclass to create the class MyObject.

When you write class MyObject(object), the class object MyObject hasn't been created in memory yet.

Python looks for a __metaclass__ attribute in the class definition. If it finds one, it uses it to create the class MyObject. If not, it uses the built-in type to create the class. If that's still unclear, look at this flow chart:

Another example:

Python· Read with the text above
class Foo(Bar):
    pass

How does Python decide here?

First, does Foo have a __metaclass__ attribute? If yes, Python uses __metaclass__ to create a class object called Foo in memory (note: a class object). If Python doesn't find __metaclass__, it looks for a __metaclass__ attribute in Bar (the parent class) and tries the same thing. If Python can't find __metaclass__ in any parent class, it looks for __metaclass__ at the module level and tries the same thing. If it still can't find __metaclass__, Python uses the built-in type to create the class object.

So __metaclass__ defines how a class behaves. Just like a class defines how an instance behaves, a metaclass defines how a class behaves. You could say a class is an instance of a metaclass.

Now we basically understand the __metaclass__ attribute. But we haven't talked about how to use it, or what you can put in it.

The answer: anything that can create a class. So what can create a class? type, or anything that uses type or subclasses type.

The main purpose of a metaclass is to automatically change a class when it's created.

You'd usually do this for an API, when you want to create classes that fit the current situation. Imagine a silly example: you decide all the attributes of all the classes in your module should be in UPPERCASE. There are several ways to do this, but one is to set __metaclass__ at the module level. That way, every class in the module is created through this metaclass, and we just need to tell the metaclass to change all attributes to uppercase.

Luckily, __metaclass__ can actually be anything you can call – it doesn't need to be a real class. So let's start with a simple function as an example.

Python· Read with the text above
# The metaclass automatically receives the arguments you'd normally pass to 'type'
def upper_attr(future_class_name, future_class_parents, future_class_attr):
    '''Return a class object with all attributes changed to uppercase'''
    #  Pick all attributes that don't start with '__'
    attrs = ((name, value) for name, value in future_class_attr.items() if not name.startswith('__'))
Python· Syntax only
# Change them to uppercase
uppercase_attr = dict((name.upper(), value) for name, value in attrs)
 
# Use 'type' to create the class object
return type(future_class_name, future_class_parents, uppercase_attr)
 
__metaclass__ = upper_attr  
#  This affects every class in this module
 
class Foo(object):
    # We could also define __metaclass__ only here, so it only affects this class
    bar = 'bip'
Python· Syntax only
print hasattr(Foo, 'bar')
# Output: False
print hasattr(Foo, 'BAR')
# Output: True
 
f = Foo()
print f.BAR
# Output: 'bip'

Using a class as the metaclass:

Python· Read with the text above
# Remember, 'type' is actually a class, just like 'str' and 'int'
# So you can inherit from type
class UpperAttrMetaClass(type):
    # __new__ is a special method called before __init__
    # __new__ creates the object and returns it
    # while __init__ just sets up the object with the arguments passed in
    # You rarely use __new__, unless you want to control how the object is created
    # Here, the object being created is a class, and we want to customise it, so we override __new__
    # You could also do things in __init__ if you want
    # Some advanced uses override the special __call__ method, but we won't here
    def __new__(upperattr_metaclass, future_class_name, future_class_parents, future_class_attr):
        attrs = ((name, value) for name, value in future_class_attr.items() if not name.startswith('__'))
        uppercase_attr = dict((name.upper(), value) for name, value in attrs)
        return type(future_class_name, future_class_parents, uppercase_attr)

But this isn't really OOP (object-oriented programming). We called type directly, and didn't override the parent's __new__ method. Let's do it this way instead:

Python· Read with the text above

class UpperAttrMetaclass(type):
    def __new__(upperattr_metaclass, future_class_name, future_class_parents, future_class_attr):
        attrs = ((name, value) for name, value in future_class_attr.items() if not name.startswith('__'))
        uppercase_attr = dict((name.upper(), value) for name, value in attrs)
 
        # Reuse the type.__new__ method
        # This is basic OOP – no magic
        return type.__new__(upperattr_metaclass, future_class_name, future_class_parents, uppercase_attr)

You may have noticed the extra parameter upperattr_metaclass. It's nothing special. The first parameter of a method always means the current instance, just like self in normal methods. I gave it a long name here to make it clear. But like self, all these parameters have their usual names. So in real code, a metaclass would look like this:

Python· Syntax only
class UpperAttrMetaclass(type):
    def __new__(cls, name, bases, dct):
        attrs = ((name, value) for name, value in dct.items() if not name.startswith('__')
        uppercase_attr  = dict((name.upper(), value) for name, value in attrs)
        return type.__new__(cls, name, bases, uppercase_attr)

If we use super, we can make it even clearer, and it helps with inheritance (yes, you can have metaclasses that inherit from metaclasses, that inherit from type):

Python· Read with the text above
class UpperAttrMetaclass(type):
    def __new__(cls, name, bases, dct):
        attrs = ((name, value) for name, value in dct.items() if not name.startswith('__'))
        uppercase_attr = dict((name.upper(), value) for name, value in attrs)
        return super(UpperAttrMetaclass, cls).__new__(cls, name, bases, uppercase_attr)

People usually use metaclasses for tricky things, like introspection (code looking at itself) and controlling inheritance. It's true that metaclasses are great for "dark magic", which leads to complicated code. But metaclasses themselves are actually very simple:

  • Intercept (catch) the creation of a class
  • Change the class
  • Return the changed class

5. Using Metaclasses

We've finally reached using metaclasses. But generally speaking, we never need them. As Tim Peters, a leader in the Python world, said (roughly):

Metaclasses are deep magic that 99% of users should never worry about. If you're wondering whether you need them, you don't. The people who actually need them know for sure that they do, and don't need an explanation of why.

The main use of metaclasses is to create APIs. A typical example is the Django ORM. It lets you write something like this:

Python· Read with the text above
class Person(models.Model):
    name = models.CharField(max_length=30)
    age = models.IntegerField()

But if you then do this:

Python· Syntax only
guy  = Person(name='bob', age='35')
print guy.age

It doesn't return an IntegerField object – it returns an int, and can even get the data straight from the database.

This is possible because models.Model defines __metaclass__, and uses some magic to turn the simple Person class you just defined into a complex hook into the database.

The Django framework makes these complicated-looking things simple by giving you a simple API that uses metaclasses. Behind the scenes, it uses this API to rebuild the code and do the real work.

Everything in Python is an object. Each one is either an instance of a class or an instance of a metaclass – except type. type is actually its own metaclass. You can't do that in pure Python; it's done with some tricks at the implementation level.
