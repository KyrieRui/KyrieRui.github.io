Threads and Processes

Threads and processes are operating system terms. Simply put, every application has its own process.

The operating system gives each process some resources to run with, like memory space.

Inside a process, you can create threads. Threads share the process's memory space, and the operating system schedules them so they can work in parallel.

We all know modern operating systems like Mac OS X, UNIX, Linux and Windows can run many tasks at the same time.

For example, you might be browsing the web, listening to music while coding, and writing a blog post in Markdown, all at once. That's multitasking – at least 3 tasks running at the same time.

And lots of other tasks are quietly running in the background too – they just don't show on your desktop.

To the operating system, one task is one process. Opening a browser starts a browser process, opening PyCharm starts a PyCharm process, and opening a Markdown editor starts a Markdown process.

These days, multi-core CPUs are very common.

But a CPU runs code one instruction after another. So you might wonder: how does a single-core CPU run many tasks at once?

Actually, the operating system makes the tasks take turns. Task 1 runs for 0.01 seconds, then it switches to task 2, which runs for 0.01 seconds, then task 3 for 0.01 seconds… and so on, again and again.

On the surface, each task takes turns. But the CPU is so fast that we can't see or feel it – it seems like all the tasks are running at the same time.

Truly running tasks in parallel can only happen on a multi-core CPU. But because there are far more tasks than CPU cores, the operating system still automatically schedules lots of tasks to take turns on each core.

Some processes don't just do one thing. A browser, for example, can play video, play audio, show articles, let you edit text and so on. These are all sub-tasks inside the browser process. To do several things at once inside one process, you need to run several "sub-tasks" at the same time. We call these sub-tasks inside a process threads.

Every process does at least one thing, so every process has at least one thread.

Of course, a process can also have many threads, and they can run at the same time. Multiple threads work the same way as multiple processes: the operating system switches quickly between threads, letting each one run briefly in turn, so they look like they're running at the same time.

So in Python, how do we run several tasks at once?

There are two options:

One is to start several processes. Each process has only one thread, but together the processes can do several tasks.

The other is to start one process, and start several threads inside it. Then the threads can do several tasks together.

There's also a third option: start several processes, and start several threads in each one. That runs even more tasks at once, but it's much more complicated, so it's rarely used in practice.

To sum up, there are 3 ways to do multitasking:

  • Multi-process
  • Multi-thread
  • Multi-process + multi-thread

When you run several tasks at once, they usually aren't completely separate. They need to communicate and coordinate. Sometimes task 1 has to pause and wait for task 2 to finish. Sometimes task 3 and task 4 can't run at the same time. So multi-process and multi-thread programs are much more complicated than the single-process, single-thread programs we've written so far.

Because they're complicated and hard to debug, we don't want to write multitasking code unless we have to.

But very often, we really can't do without it.

Think about watching a movie on a computer. One thread must play the video, and another must play the audio. With only one thread, you'd have to play all the video first and then all the audio, or the other way round. Clearly that won't work.

First, check which tasks can be done on their own

Before talking about threads and processes, let's break the task down clearly: does the calculation for each record depend on the others? Do the results need to be shown in the same order as the input, or can each one be shown as soon as it's done? These choices affect how you write the code.

The thread pool example below is for Python on your own computer. The Python that runs in a browser doesn't have the same thread and process abilities as your computer, so please run this one in a local terminal.

Python· Read with the text above
from concurrent.futures import ThreadPoolExecutor


def double_minutes(minutes):
    return minutes * 2


with ThreadPoolExecutor(max_workers=2) as pool:
    results = list(pool.map(double_minutes, [15, 0, 10]))
print(results)

Output:

Text
[30, 0, 20]

The results from this map come out in the same order as the input. That doesn't mean the tasks themselves ran strictly in that order. Try changing the input to an empty list – the result should be [].

This task is too small. We're only using a thread pool here to see how it works – it can't prove that threads are always faster. To compare speed, you must keep the amount of work, the environment and the way you measure the same. When people talk about the GIL, they also need to say which interpreter and build they mean – you can't apply a conclusion about one CPython setup to every Python environment. First learn to tell apart computing, waiting and shared state, then choose your tool.

Multithreaded Programming

After a thread is created, it doesn't stay in one state the whole time. Its states are roughly:

  • New – just created
  • Runnable – ready, waiting to be scheduled
  • Running – running
  • Blocked – stuck; this could be waiting, waiting for a lock, or sleeping
  • Dead – finished

Threads have different states, and also different kinds. Roughly:

  • Main thread
  • Child threads
  • Daemon threads (background threads)
  • Foreground threads

Now that we know a bit about these, let's look at some code.

1. Creating Threads

Python has two modules for working with threads: thread and threading.

The first is a low-level module for more basic operations. It's not often used in normal application development.

So let's use threading for our example:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import time
import threading


class MyThread(threading.Thread):
    def run(self):
        for i in range(5):
            print(f'thread {self.name}, @number: {i}')
            time.sleep(1)


def main():
    print("Start main threading")

    # Create three threads
    threads = [MyThread() for i in range(3)]
    # Start the three threads
    for t in threads:
        t.start()

    print("End Main threading")


if __name__ == '__main__':
    main()

2. Joining Threads (the join method)

From the output above, we can see the child threads are still running after the main thread has ended. What if we want the main thread to wait for the child threads to finish before it exits?

That's when we use the join method.

Let's add some code to the example above:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import time
import threading


class MyThread(threading.Thread):
    def run(self):
        for i in range(5):
            print(f'thread {self.name}, @number: {i}')
            time.sleep(1)


def main():
    print("Start main threading")

    # Create three threads
    threads = [MyThread() for i in range(3)]
    # Start the three threads
    for t in threads:
        t.start()

    # Call join on each new thread, one after another
    for t in threads:
        t.join()

    print("End Main threading")


if __name__ == '__main__':
    main()

From the output, you can clearly see that, compared with the example above, the main thread waits until the child threads have finished before it ends.

3. Thread Synchronisation and Locks

When several threads load and use data, the data often gets out of sync. To fix this, we can put a lock on a resource: a thread must get the lock before it can use the resource.

The threading module gives us a Lock:

Python· Run it on your own computer
lock = threading.Lock()

Get (acquire) the lock in a thread:

Python· Run it on your own computer
lock.acquire()

When we're done, we must release the lock:

Python· Run it on your own computer
lock.release()

To let the same thread ask for the same resource several times, Python has a re-entrant lock (RLock). Inside, an RLock keeps a Lock and a counter variable. The counter records how many times acquire was called, so the resource can be acquired many times. Only after a thread has released every acquire can other threads get the resource.

How do you create a re-entrant lock? Just one line:

Python· Run it on your own computer
r_lock = threading.RLock()

4. Condition Variables

Locks can keep threads in sync, but in more complicated situations, we need to check some conditions around the lock.

Python provides the Condition object.

With a Condition object, you can wait to process data until some event happens or some condition is met. Besides the acquire and release methods of a Lock, a Condition also has wait and notify methods.

A thread first acquires the condition variable's lock. If the condition isn't met, the thread waits. If it is met, the thread runs, and can even notify other threads. Other threads that are waiting check the condition again when they get the notification.

You can think of it like this: different threads take turns acquiring the lock. If a thread's condition isn't met, it's put into a "waiting pool" (of the Lock or RLock), until another thread notifies it and it checks the condition again. Repeating this over and over solves complicated synchronisation problems.

This pattern is often used for the producer–consumer pattern. Look at this example of a buyer and seller shopping online:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import threading, time


class Consumer(threading.Thread):
    def __init__(self, cond, name):
        # Set up
        super(Consumer, self).__init__()
        self.cond = cond
        self.name = name

    def run(self):
        # Make sure the Producer's code runs first
        time.sleep(1)
        self.cond.acquire()
        print(self.name + ': If I buy these two items together, can I get a discount?')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': I have placed the order. Please change the price.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Got it. My payment went through.')
        self.cond.notify()
        self.cond.release()
        print(self.name + ': Waiting for delivery')


class Producer(threading.Thread):
    def __init__(self, cond, name):
        super(Producer, self).__init__()
        self.cond = cond
        self.name = name

    def run(self):
        self.cond.acquire()
        # Release the lock and pause the thread here, until it's notified and gets the lock back
        self.cond.wait()
        print(self.name + ': Sure, go ahead and place the order.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Done, I have changed it.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Payment received. I will ship it right away.')
        self.cond.release()
        print(self.name + ': Shipping the items')


cond = threading.Condition()
consumer = Consumer(cond, 'Buyer (Two Drops)')
producer = Producer(cond, 'Seller (Three Drops)')
consumer.start()
producer.start()

5. Communication Between Threads

If a program has several threads, they'll need to talk to each other. So how do we safely pass information or data between threads?

Probably the safest way to send data from one thread to another is to use a queue from the queue library. Create a Queue object shared by the threads, and the threads use put() and get() to add items to the queue or take them out.

Python· Run it on your own computer
# -*- coding: UTF-8 -*-
from queue import Queue
from threading import Thread


def write(q):
    # The thread that writes data
    for value in ['Two Drops', 'Three Drops', 'Four Drops']:
        print(f'Value written to the Queue: {value}')
        q.put(value)
    q.put(None)  # Put an "end" marker when finished


def read(q):
    # The thread that reads data
    while True:
        value = q.get(True)
        if value is None:  # Stop when we read the end marker
            break
        print(f'Value read from the Queue: {value}')


if __name__ == '__main__':
    q = Queue()
    t1 = Thread(target=write, args=(q,))
    t2 = Thread(target=read, args=(q,))
    t1.start()
    t2.start()

Output:

Text
Value written to the Queue: Two Drops
Value written to the Queue: Three Drops
Value read from the Queue: Two Drops
Value written to the Queue: Four Drops
Value read from the Queue: Three Drops
Value read from the Queue: Four Drops

Python also has an Event object for communication between threads. It's a signal flag set by a thread. Other threads can wait until the signal is set.

The Event object gives a simple way for threads to communicate. It lets you set the signal, clear the signal, and wait.

  • Setting the signal

Use the Event's set() method to set its internal signal flag to true. The Event object has an isSet() method to check the flag. After you call set(), isSet() returns true.

  • Clearing the signal

Use the Event's clear() method to clear the internal signal flag (set it to false). After you call clear(), isSet() returns false.

  • Waiting

The Event's wait method returns quickly only when the internal signal is true. When the flag is false, wait keeps waiting until it becomes true.

Example:

Python· Run it on your own computer
# -*- coding: UTF-8 -*-

import threading


class mThread(threading.Thread):
    def __init__(self, threadname):
        threading.Thread.__init__(self, name=threadname)

    def run(self):
        # Use the global Event object
        global event
        # Check the Event's internal signal flag
        if event.isSet():
            event.clear()
            # Add a timeout as a safety net: checking isSet() and calling clear() is not one atomic step,
            # so two threads could both pass the check and both wait(), with only one set() to wake them
            event.wait(timeout=1)
            print(self.getName())
        else:
            print(self.getName())
            # Set the Event's internal signal flag
            event.set()

# Create an Event object
event = threading.Event()
# Set the Event's internal signal flag
event.set()
t1 = []
for i in range(10):
    t = mThread(str(i))
    # Build a list of threads
    t1.append(t)

for i in t1:
    # Run the threads
    i.start()

5

6. Background (Daemon) Threads

By default, when the main thread exits, child threads keep running even if they weren't joined. If you want the child threads to stop when the main thread exits, you need to make them background (daemon) threads. Python provides the setDaemon method for this.

Processes

Multithreading in Python isn't really true multithreading. If you want to make full use of a multi-core CPU, in Python you usually need to use multiple processes.

Python has a really handy package for multiple processes called multiprocessing. You just define a function, and Python does everything else.

With this package, it's easy to go from one process to running things in parallel. multiprocessing supports child processes, communication and shared data, and different kinds of synchronisation. It provides parts like Process, Queue, Pipe and Lock.

1. The Process Class

The class for creating a process: Process([group [, target [, name [, args [, kwargs]]]]])

  • target is the thing to call
  • args is a tuple of positional arguments for it
  • kwargs is a dictionary of keyword arguments for it
  • name is a nickname
  • group isn't really used

Here's an example that creates a function and runs it in several processes:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import multiprocessing
import time


def worker(interval, name):
    print(name + '[start]')
    time.sleep(interval)
    print(name + '[end]')


if __name__ == "__main__":
    p1 = multiprocessing.Process(target=worker, args=(2, 'Two Drops 1'))
    p2 = multiprocessing.Process(target=worker, args=(3, 'Two Drops 2'))
    p3 = multiprocessing.Process(target=worker, args=(4, 'Two Drops 3'))

    p1.start()
    p2.start()
    p3.start()

    print("The number of CPU is:" + str(multiprocessing.cpu_count()))
    for p in multiprocessing.active_children():
        print("child   p.name:" + p.name + "\tp.id" + str(p.pid))
    print("END!!!!!!!!!!!!!!!!!")

2. Making a Process into a Class

We can also make a process into a class. In the example below, when process p calls start(), the run() method is called automatically.

Python· Run it on your own computer
# -*- coding: UTF-8 -*-

import multiprocessing
import time


class ClockProcess(multiprocessing.Process):
    def __init__(self, interval):
        multiprocessing.Process.__init__(self)
        self.interval = interval

    def run(self):
        n = 5
        while n > 0:
            print(f"Current time: {time.ctime()}")
            time.sleep(self.interval)
            n -= 1


if __name__ == '__main__':
    p = ClockProcess(3)
    p.start()

3. The daemon Attribute

To see what the daemon attribute does, look at these two examples – one with daemon and one without – and compare the output.

Without the daemon attribute:

Now add the daemon attribute to process p in the same example:

Python· Run it on your own computer
# -*- coding: UTF-8 -*-

import multiprocessing
import time


def worker(interval):
    print(f'Work start time: {time.ctime()}')
    time.sleep(interval)
    print(f'Work end time: {time.ctime()}')


if __name__ == '__main__':
    p = multiprocessing.Process(target=worker, args=(3,))
    p.daemon = True
    p.start()
    print('[END]')

Text

From the output, you can see that if a child process has daemon set, it ends when the main process ends. That's why the child process's messages weren't printed.

4. The join Method

Carrying on from the example above: what if we want the child process to finish?

We can use the join method. Its main job is to block the current process until the process that called join has finished, and then carry on with the current process.

Here's the example with join added:

Python· Run it on your own computer
import multiprocessing
import time


def worker(interval):
    print(f'Work start time: {time.ctime()}')
    time.sleep(interval)
    print(f'Work end time: {time.ctime()}')


if __name__ == '__main__':
    p = multiprocessing.Process(target=worker, args=(3,))
    p.daemon = True
    p.start()
    p.join()
    print('[END]')

Output:

Text
Work start time: Tue Oct 10 11:30:08 2017
Work end time: Tue Oct 10 11:30:11 2017
[END]

5. Pool

If we need lots of child processes, do we have to create them one by one?

Of course not! We can use a process pool to create child processes in bulk.

Example:

Python· Run it on your own computer
# -*- coding: UTF-8 -*-

from multiprocessing import Pool
import os, time, random


def long_time_task(name):
    print(f'Process name: {name}; process PID: {os.getpid()} ')
    start = time.time()
    time.sleep(random.random() * 3)
    end = time.time()
    print(f'Process {name} ran for {end - start} seconds')


if __name__ == '__main__':
    print(f'Main process PID: {os.getpid()}')
    p = Pool(4)
    for i in range(6):
        p.apply_async(long_time_task, args=(i,))
    p.close()
    # Wait for all child processes to finish before ending the main process
    p.join()
    print('[End]')

Output:

Text

Process name: 0; process PID: 1492
Process name: 1; process PID: 12232
Process name: 2; process PID: 4332
Process name: 3; process PID: 11604
Process 2 ran for 0.6500370502471924 seconds
Process name: 4; process PID: 4332
Process 1 ran for 1.0830621719360352 seconds
Process name: 5; process PID: 12232
Process 5 ran for 0.029001712799072266 seconds
Process 4 ran for 0.9720554351806641 seconds
Process 0 ran for 2.3181326389312744 seconds
Process 3 ran for 2.5331451892852783 seconds

One thing to note: calling join() on a Pool object waits for all child processes to finish. You must call close() before join(), and after close() you can't add any new processes.

Look carefully at the output. Child processes 0, 1, 2 and 3 start straight away, but child process 4 has to wait until one of the earlier ones finishes. That's because the default size of Pool on my computer is 4, so at most 4 processes run at the same time. This is a limit Pool sets on purpose – it's not a limit of the operating system. If you change it to:

Python· Run it on your own computer
p = Pool(5)

then 5 processes can run at the same time.

6. Communication Between Processes

Processes definitely need to talk to each other. The operating system provides many ways for processes to communicate. Python's multiprocessing module wraps these low-level mechanisms and gives you several ways to exchange data, like Queue and Pipes.

Take Queue as an example. In the parent process, we create two child processes: one writes data into the Queue, and the other reads data from it:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

from multiprocessing import Process, Queue
import os, time, random


def write(q):
    # The process that writes data
    print(f'Writer process PID: {os.getpid()}')
    for value in ['Two Drops', 'Three Drops', 'Four Drops']:
        print(f'Value written to the Queue: {value}')
        q.put(value)
        time.sleep(random.random())


def read(q):
    # The process that reads data
    print(f'Reader process PID: {os.getpid()}')
    while True:
        value = q.get(True)
        print(f'Value read from the Queue: {value}')


if __name__ == '__main__':
    # The parent process creates the Queue and passes it to each child process
    q = Queue()
    pw = Process(target=write, args=(q,))
    pr = Process(target=read, args=(q,))
    # Start child process pw
    pw.start()
    # Start child process pr
    pr.start()
    # Wait for pw to finish
    pw.join()
    # pr has an endless loop, so we can't wait for it to finish – we have to force it to stop
    pr.terminate()

Value written to the Queue: Three Drops
Value read from the Queue: Three Drops
Value written to the Queue: Four Drops
Value read from the Queue: Four Drops
