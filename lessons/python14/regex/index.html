A First Look at Python Regular Expressions

A regular expression (regex) is a special sequence of characters used to check whether a string matches a pattern that we set.

Python added the re module in version 1.5. It provides Perl-style regular expression patterns, and gives Python the full power of regular expressions.

Let's get to know regular expressions step by step, with examples.

Say we want to check whether a string contains some character or characters. Usually we use built-in functions, like this:

Python· Runs on this page
# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Check whether it contains the string "TwoDrops", using Python's built-in functions

print(f'Does it contain "TwoDrops"? {a.index("TwoDrops") > -1}')
print(f'Does it contain "TwoDrops"? {"TwoDrops" in a}')

Output:

Text
Does it contain "TwoDrops"? True
Does it contain "TwoDrops"? True

So what if we use a regular expression?

As we said, Python gives us the re module for all regular expression features. Let's use one of its functions first:

Python· Syntax only
re.findall(pattern, string[, flags])

This function finds all the parts of the string that match the regular expression, and returns them as a list. Like this:

Python· Runs on this page

import re

# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Regular expression

findall = re.findall('TwoDrops', a)
print(findall)

if len(findall) > 0:
    print('a contains the string "TwoDrops"')
else:
    print('a does not contain the string "TwoDrops"')

Output:

Text
['TwoDrops']
a contains the string "TwoDrops"

From the output, it does the same job as the built-in functions. But I must stress: this example is only to help us understand regular expressions. Writing a regex like this is pointless. Why?

Because if a problem can be solved with Python's built-in functions, there's no need for a regular expression – it's just extra work. Also, the "regular expression" in this example is just a fixed string, not a rule. The soul of a regular expression is its rules, so this doesn't mean much.

So how do you write a regex rule? Don't rush – let's go step by step. Let's start simple: find all the lowercase letters in the string. The first argument of findall is the regex rule. [a-z] matches any lowercase letter. The second argument is just the string to search. Like this:

Python· Runs on this page

import re

# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Pick out all the lowercase English letters in a

re_findall = re.findall('[a-z]', a)

print(re_findall)

Output:

Text
['w', 'o', 'r', 'o', 'p', 's', 't', 'w', 'o', 'w', 'a', 't', 'e', 'r', 'l', 'i', 'a', 'n', 'g', 'd', 'i', 'a', 'n', 's', 'h', 'u', 'i', 'r', 'a', 's', 's', 'o', 'o', 't', 's', 'o', 'd', 'e', 'r', 'e', 'a', 'd', 'i', 'n', 'g', 'i', 't', 'h']

Now we've got all the lowercase letters in the string.

Prepare examples that should match AND examples that shouldn't

We've built up the rules step by step. Now let's make the requirement a bit narrower: a name must be made of one or more English letters. First prepare three inputs for it, then look at the results:

Python· Runs on this page
import re

pattern = r'[A-Za-z]+'
for name in ['Python', 'Python20', '']:
    print(bool(re.fullmatch(pattern, name)))

Output:

Text
True
False
False

fullmatch requires the whole text to match the rule. If you used search instead, the 'Python' inside 'Python20' would be found – but that doesn't mean the whole name meets the requirement. First be clear whether you mean "contains a part that matches" or "the whole thing matches", then choose your function.

Now add 'python', 'Python!' and 'Two Drops' yourself. You should get True, False, False. The last one is False because of the space – our rule only allows English letters.

When you use index() to find a substring and it isn't there, it raises a ValueError – it does not return -1 for you to compare. If you only want to check whether some plain text is there, 'target' in text is more direct. The more complicated your rule, the more you need to keep some examples that should match, some that shouldn't, and some edge cases.

Character Sets

OK, with the examples above we've had a first look at Python regular expressions. You might ask: what other rules are there? What does each letter mean?

Don't rush. Later in this chapter there's a list of regex rules, and you can easily find these on the internet too. So for now, let's go deeper into understanding regular expressions, and talk about character sets.

A character set is a group of characters inside a pair of square brackets []. With a character set, you can match one of several characters.

For example, C[ET]O matches CEO or CTO. So [ET] means one E or one T. [a-z], which we saw above, means any one lowercase letter. Here the hyphen - defines a range of characters in a row. You can put several ranges inside, like [0-9a-fA-F], which matches a single hexadecimal digit, upper or lower case. Note: the order of characters and ranges inside doesn't affect the result at all.

All of this is to show that the characters inside a character set [] have an "OR" relationship. Let's look at an example:

Python· Runs on this page

import re
a = 'uav,ubv,ucv,uwv,uzv,ucv,uov'

# Character sets

# Find strings where the character between u and v is a or b or c
findall = re.findall('u[abc]v', a)
print(findall)
# For letters or digits in a row, you can use -
l = re.findall('u[a-c]v', a)
print(l)

# Find strings where the character between u and v is NOT a or b or c
re_findall = re.findall('u[^abc]v', a)
print(re_findall)

Output:

Text
['uav', 'ubv', 'ucv', 'ucv']
['uav', 'ubv', 'ucv', 'ucv']
['uwv', 'uzv', 'uov']

The example uses a negated character set: if you put a caret ^ right after the opening bracket [, the set is flipped ("not these"). Remember: a negated character set must still match one character. For example, q[^u] does not mean "match a q that isn't followed by a u". It means "match a q followed by a character that isn't u". Compare with the output of the example above to understand.

Regular expressions also have some built-in rules. For example, \d matches any digit character – it's the same as [0-9]. Here's an example that explains these special characters using character sets.

For Python string regexes, Unicode rules are used by default, so \d can also match things like full-width digits, and \w isn't limited to English letters, digits and underscores. Only when you limit it to ASCII rules can you think of them as the ASCII ranges below. When writing regex patterns, prefer raw strings like r"\d", so the backslash isn't handled by normal string rules.

Python· Runs on this page
import re

a = 'uav_ubv_ucv_uwv_uzv_ucv_uov&123-456-789'

# Shorthand character sets

# \d is like [0-9] – matches all digit characters
# \D is like [^0-9] – matches all non-digit characters
findall1 = re.findall('\d', a)
findall2 = re.findall('[0-9]', a)
findall3 = re.findall('\D', a)
findall4 = re.findall('[^0-9]', a)
print(findall1)
print(findall2)
print(findall3)
print(findall4)

# \w matches any "word" character, including underscore – like [A-Za-z0-9_]
findall5 = re.findall('\w', a)
findall6 = re.findall('[A-Za-z0-9_]', a)
print(findall5)
print(findall6)

Output:

Text
['1', '2', '3', '4', '5', '6', '7', '8', '9']
['1', '2', '3', '4', '5', '6', '7', '8', '9']
['u', 'a', 'v', '_', 'u', 'b', 'v', '_', 'u', 'c', 'v', '_', 'u', 'w', 'v', '_', 'u', 'z', 'v', '_', 'u', 'c', 'v', '_', 'u', 'o', 'v', '&', '-', '-']
['u', 'a', 'v', '_', 'u', 'b', 'v', '_', 'u', 'c', 'v', '_', 'u', 'w', 'v', '_', 'u', 'z', 'v', '_', 'u', 'c', 'v', '_', 'u', 'o', 'v', '&', '-', '-']
['u', 'a', 'v', '_', 'u', 'b', 'v', '_', 'u', 'c', 'v', '_', 'u', 'w', 'v', '_', 'u', 'z', 'v', '_', 'u', 'c', 'v', '_', 'u', 'o', 'v', '1', '2', '3', '4', '5', '6', '7', '8', '9']
['u', 'a', 'v', '_', 'u', 'b', 'v', '_', 'u', 'c', 'v', '_', 'u', 'w', 'v', '_', 'u', 'z', 'v', '_', 'u', 'c', 'v', '_', 'u', 'o', 'v', '1', '2', '3', '4', '5', '6', '7', '8', '9']

Quantifiers

Let's keep going deeper into regular expressions. This part is about quantifiers (how many times). Why do we need them? Think about it: if you want to match dozens or hundreds of characters, do you really want to write them one by one? That's why quantifiers exist.

The syntax of a quantifier is {min,max}. min and max are non-negative integers. If there's a comma but no max, there's no upper limit. If there's no comma and no max, it repeats exactly min times. For example, \b[1-9][0-9]{3}\b matches a number from 1000 to 9999 (\b means a word boundary), and \b[1-9][0-9]{2,4}\b matches a number from 100 to 99999.

Here's an example that matches English words of 4 to 7 letters in a string:

Python· Runs on this page
import re

a = 'java*&39android##@@python'

# Quantifiers

findall = re.findall('[a-z]{4,7}', a)
print(findall)

Output:

Text
['java', 'android', 'python']

Note: there's a difference between greedy and non-greedy matching. Let's look at what they mean:

Greedy mode: it reads in the whole string at once. If it doesn't match, it spits out the rightmost character and tries again, until it finds a match or the string is empty. Its aim is to read as many characters as possible, so it returns as soon as it finds its first match.

Lazy mode: it starts from the left of the string and tries to match while reading as few characters as possible. If that fails, it reads one more character and tries again, and so on. When it finds a match, it returns it, then carries on matching until the end of the string.

The example above is greedy. How do we use non-greedy (lazy) mode instead?

To use non-greedy mode, add a ?. Let's change the example:

Python· Runs on this page
import re

a = 'java*&39android##@@python'

# Greedy vs non-greedy

re_findall = re.findall('[a-z]{4,7}?', a)
print(re_findall)

Output:

Text
['java', 'andr', 'pyth']

From the output, android only gave andr, and python only gave pyth, because we're using lazy mode here.

There are also some special characters that mean "how many", like:

?: tells the engine to match the character before it 0 or 1 times

+: tells the engine to match the character before it 1 or more times

*: tells the engine to match the character before it 0 or more times

Putting it all together gives this table:

Greedy Lazy Description
? ?? Zero or one time, same as {0,1}
+ +? One or more times, same as {1,}
* *? Zero or more times, same as {0,}
{n} {n}? Exactly n times
{n,m} {n,m}? At least n and at most m times
{n,} {n,}? At least n times

Boundaries and Groups

We've already spent a lot of space on the points above. Now let's introduce boundary matchers and groups.

The common boundary matchers are:

Syntax Description
^ Matches the start of the string (with multiple lines, the start of each line)
$ Matches the end of the string (with multiple lines, the end of each line)
\A Matches only the start of the string
\Z Matches only the end of the string
\b Matches the boundary between \w and \W
\B [^\b] (not a word boundary)

Groups: an expression inside round brackets is a group. A group (...) treats those characters as one unit. You can have several groups – each new group gets the next number (1, 2, 3…). You can also put a quantifier after a group.

re.sub

In real work, we often need to replace characters in a string. That's when we use the function def sub(pattern, repl, string, count=0, flags=0). re.sub has five parameters: three required ones – pattern, repl, string – and two optional ones – count, flags.

Here's what each parameter means:

Parameter Description
pattern The regex pattern string
repl Short for "replacement" – what to replace matches with
string The string to process, where replacements will happen
count Of the matches found by pattern, how many to replace (from the start)
flags Regex modifiers (flags)

Look at the example below – the comments explain it clearly. The main thing to notice is that the second argument can be a function. This is what makes sub so powerful. For example, the function convert in the example checks each matched character and replaces it with something different.

Python· Runs on this page
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import re

a = 'Python*Android*Java-888'

# Replace every * in the string with &
sub1 = re.sub('\*', '&', a)
print(sub1)

# Replace only the first * in the string with &
sub2 = re.sub('\*', '&', a, 1)
print(sub2)


# Replace every * with &, and every - with |

# 1. First, define a function
def convert(value):
    group = value.group()
    if (group == '*'):
        return '&'
    elif (group == '-'):
        return '|'


# The second argument (what to replace with) can be a function
sub3 = re.sub('[\*-]', convert, a)
print(sub3)

Output:

Text
Python&Android&Java-888
Python&Android*Java-888
Python&Android&Java|888

re.match and re.search

The re.match function

Syntax:

Python· Read with the text above
re.match(pattern, string, flags=0)

re.match tries to match a pattern at the start of the string. If it doesn't match at the start, match() returns None.

The re.search function

Syntax:

Python· Read with the text above
re.search(pattern, string, flags=0)

re.search scans the whole string and returns the first match it finds.

re.match and re.search take basically the same parameters:

Parameter Description
pattern The regular expression to match
string The string to search
flags Flags that control how matching works, e.g. whether it's case-sensitive

So what's the difference?

re.match only matches at the start of the string. If the start doesn't match the regex, matching fails and it returns None. re.search searches the whole string until it finds a match. That's the difference.

There are lots of detailed explanations of re.match and re.search online, but personally, I prefer to use re.findall.

Look at the example below to compare re.search and re.findall, and to see how multiple groups work. Read the comments and compare with the output:

Example:

Python· Runs on this page

#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

# Extract an image address

import re

a = '<img src="https://s-media-cache-ak0.pinimg.com/originals/a8/c4/9e/a8c49ef606e0e1f3ee39a7b219b5c05e.jpg">'

# Using re.search
search = re.search('<img src="(.*)">', a)
# group(0) is the whole match
print(search.group(0))
print(search.group(1))

# Using re.findall
findall = re.findall('<img src="(.*)">', a)
print(findall)

# Using several groups (e.g. we want both the img tag name and the image address)
re_search = re.search('<(.*) src="(.*)">', a)
# Print img
print(re_search.group(1))
# Print the image address
print(re_search.group(2))
# Print img and the image address together, as a tuple
print(re_search.group(1, 2))
# Or use groups()
print(re_search.groups())

Output:

Finally: regular expressions are a very powerful tool. They can usually solve problems that the built-in string functions can't, and most programming languages have them. Python is used for lots of things, but web scraping and data analysis especially can't do without regular expressions. So regular expressions are really important for learning Python.

7.  18-digit Chinese ID number (digits, may end in x): ^((\d{18})|([0-9x]{18})|([0-9X]{18}))$
8.  Valid username (starts with a letter, 5–16 characters, letters, digits and underscores allowed): ^[a-zA-Z][a-zA-Z0-9_]{4,15}$
9.  Password (starts with a letter, 6–18 long, only letters, digits and underscores): ^[a-zA-Z]\w{5,17}$
10. Strong password (must mix capital letters, lowercase letters and digits, no special characters, 8–10 long): ^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,10}$  
11. Date format: ^\d{4}-\d{1,2}-\d{1,2}
12. The 12 months of a year (01–09 and 1–12): ^(0?[1-9]|1[0-2])$
13. The 31 days of a month (01–09 and 1–31): ^((0?[1-9])|((1|2)[0-9])|30|31)$
14. Money input formats:
      a. We accept four ways of writing money: "10000.00", "10,000.00", and without cents, "10000" and "10,000": ^[1-9][0-9]*$
      b. That means any number not starting with 0. But it also means the single character "0" fails, so we use this instead: ^(0|[1-9][0-9]*)$
      c. Either a 0, or a number not starting with 0. We could also allow a minus sign at the start: ^(0|-?[1-9][0-9]*)$
      d. That means a 0, or a possibly negative number not starting with 0. Let's allow users to start with 0, and remove the minus sign, since money can't be negative. Next, let's allow an optional decimal part: ^[0-9]+(.[0-9]+)?$
      e. Note that there must be at least 1 digit after the decimal point, so "10." fails, but "10" and "10.2" pass: ^[0-9]+(.[0-9]{2})?$
      f. This requires exactly two digits after the decimal point. If you think that's too strict, use this: ^[0-9]+(.[0-9]{1,2})?$
      g. This lets users write just one decimal place. Next, let's think about commas in the number: ^[0-9]{1,3}(,[0-9]{3})*(.[0-9]{1,2})?$
      h. 1 to 3 digits, followed by any number of (comma + 3 digits), with commas optional instead of required: ^([0-9]+|[0-9]{1,3}(,[0-9]{3})*)(.[0-9]{1,2})?$
15. XML file: ^([a-zA-Z]+-?)+[a-zA-Z0-9]+\\.[x|X][m|M][l|L]$
16. Regex for Chinese characters: [一-龥]
17. Double-byte characters: [^\x00-\xff]    (includes Chinese characters; can be used to work out string length, counting a double-byte character as 2 and an ASCII character as 1)
18. Regex for blank lines: \n\s*\r    (can be used to delete blank lines)
19. Regex for HTML tags: <(\S*?)[^>]*>.*?</\1>|<.*? />    (the versions shared online are terrible; this one only partly works and still can't handle complex nested tags)
20. Regex for whitespace at the start and end: ^\s*|\s*$ or (^\s*)|(\s*$)    (can be used to remove whitespace – spaces, tabs, form feeds and so on – at the start and end of a line; very useful)
21. Tencent QQ number: [1-9][0-9]{4,}    (QQ numbers start from 10000)
22. Chinese postcode: [1-9]\d{5}(?!\d)    (Chinese postcodes are 6 digits)
23. IP address: \d+\.\d+\.\d+\.\d+    (useful for extracting IP addresses)
24. IP address: ((?:(?:25[0-5]|2[0-4]\\d|[01]?\\d?\\d)\\.){3}(?:25[0-5]|2[0-4]\\d|[01]?\\d?\\d))  
25. IPv6 address: (([0-9a-fA-F]{1,4}:){7,7}[0-9a-fA-F]{1,4}|([0-9a-fA-F]{1,4}:){1,7}:|([0-9a-fA-F]{1,4}:){1,6}:[0-9a-fA-F]{1,4}|([0-9a-fA-F]{1,4}:){1,5}(:[0-9a-fA-F]{1,4}){1,2}|([0-9a-fA-F]{1,4}:){1,4}(:[0-9a-fA-F]{1,4}){1,3}|([0-9a-fA-F]{1,4}:){1,3}(:[0-9a-fA-F]{1,4}){1,4}|([0-9a-fA-F]{1,4}:){1,2}(:[0-9a-fA-F]{1,4}){1,5}|[0-9a-fA-F]{1,4}:((:[0-9a-fA-F]{1,4}){1,6})|:((:[0-9a-fA-F]{1,4}){1,7}|:)|fe80:(:[0-9a-fA-F]{0,4}){0,4}%[0-9a-zA-Z]{1,}|::(ffff(:0{1,4}){0,1}:){0,1}((25[0-5]|(2[0-4]|1{0,1}[0-9]){0,1}[0-9])\\.){3,3}(25[0-5]|(2[0-4]|1{0,1}[0-9]){0,1}[0-9])|([0-9a-fA-F]{1,4}:){1,4}:((25[0-5]|(2[0-4]|1{0,1}[0-9]){0,1}[0-9])\\.){3,3}(25[0-5]|(2[0-4]|1{0,1}[0-9]){0,1}[0-9]))
26. URL link: ((http|ftp|https)://)(([a-zA-Z0-9\._-]+\.[a-zA-Z]{2,6})|([0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}))(:[0-9]{1,4})*(/[a-zA-Z0-9\&%_\./-~-]*)?
