1. Python's Magic Methods

In Python, all methods wrapped in double underscores __ are called magic methods. The one we've used most is __init__.

What are magic methods for?

With magic methods, we can write beautiful code and wrap complicated logic into simple methods.

So what magic methods does a class have?

We can use Python's built-in dir() to list all the magic methods in a class. For example:

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    pass


if __name__ == '__main__':
    print(dir(User()))

Output:

Text
['__class__', '__delattr__', '__dict__', '__dir__', '__doc__', '__eq__', '__format__', '__ge__', '__getattribute__', '__gt__', '__hash__', '__init__', '__init_subclass__', '__le__', '__lt__', '__module__', '__ne__', '__new__', '__reduce__', '__reduce_ex__', '__repr__', '__setattr__', '__sizeof__', '__str__', '__subclasshook__', '__weakref__']

You can see a class has quite a lot of magic methods. But we only need to know some of the common, useful ones.

First, pick one thing you want your object to do

You don't need to memorise every magic method at once. Say we want to use len() to see how many entries a log has. Let's write the least code needed for just that:

Python· Runs on this page
Practise on the challenge page →
class Logbook:
    def __init__(self):
        self.records = []

    def __len__(self):
        return len(self.records)


book = Logbook()
print(len(book), bool(book))
book.records.append(15)
print(len(book), bool(book))

Output:

Text
0 False
1 True

We only wrote __len__. If there's no separate __bool__, Python can use the length to decide if the object is true or false. So an empty log is False, and a log with one entry is True. Understanding these links between normal operations and magic methods is more important than memorising a long list of double-underscore names.

Add two more entries yourself and check that the length is 3. Then think: if all you need is to store a list of minutes, isn't a normal list already enough? A custom class should be worth it because of behaviour you really need – not just to use every magic method.

You can come back and reread the later parts on descriptors and attribute access when you need them. For now, if you can explain how a normal operation triggers a method you defined, that's enough. Go deeper step by step.

2. Construction (__new__) and Initialisation (__init__)

From what we've learned, when we define a class, we often use __init__(self) to set up attributes when an object is created.

Like this:

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __init__(self, name, age):
        self.name = name;
        self.age = age;

user=User('Two Drops',23)

Actually, creating an object happens in two steps: first the object is created, then it is initialised.

__new__ creates the object and returns this new instance. __init__ only uses the arguments passed in to set up (initialise) that instance. __new__ is always called when an instance is created, but __init__ isn't always. For example, when an instance is loaded back with pickle.load, __init__ is not called.

def __new__(cls) is called before def __init__(self), and its job is to return an instance. One more thing: __new__ must always return an instance of the class, while __init__ can't return anything except None.

One more detail: __new__ can return an object of a different type. If what it returns isn't an instance of the current class, the current class's __init__ won't be called. The two-step idea above applies to the normal case of creating an instance of the current class.

Here's an example:

Python· Runs on this page
Practise on the challenge page →
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __new__(cls, *args, **kwargs):
        # Print some info from inside __new__
        print('def __new__ was called')
        print(args)
        # Finally, return the parent class's __new__
        return super(User, cls).__new__(cls)

    def __init__(self, name, age):
        print('def __init__ was called')
        self.name = name
        self.age = age


if __name__ == '__main__':
    usr = User('Two Drops', 23)

Look at the output:

Text
def __new__ was called
('Two Drops', 23)
def __init__ was called

From the output, we can see how an object is created: first __new__ is called to create the object, then the arguments are passed to __init__ to set it up.

In real projects, you'll rarely use __new__, unless you want to control how objects are created. When people talk about __new__, it's usually connected to metaclasses.

And when an object's life ends, the destructor __del__ is called. But this happens when Python cleans up the object itself (garbage collection).

3. Controlling Attribute Access

We said before that Python doesn't have real private attributes. This makes it harder to "wrap up" (encapsulate) Python classes. Sometimes we want private attributes in Python, with public get and set methods to access them. Python can actually do this kind of wrapping with magic methods.

Method What it does
__getattr__(self, name) Defines what happens when you try to access an attribute that doesn't exist. So by overriding it, you can catch spelling mistakes and redirect them, or warn about old attributes that shouldn't be used any more.
__setattr__(self, name, value) Defines what happens when you assign or change an attribute. It lets you assign to an attribute whether it exists or not. Be careful: when you write __setattr__, avoid infinite recursion errors.
__delattr__(self, name) __delattr__ is a lot like __setattr__, but it defines what happens when you delete an attribute. When writing __delattr__, also avoid infinite recursion errors.
__getattribute__(self, name) __getattribute__ defines what happens every time an attribute is accessed. By comparison, __getattr__ only works when the attribute doesn't exist. So in Python versions that support __getattribute__, it is always called before __getattr__. __getattribute__ must also avoid infinite recursion errors.

From the table, you can see it's easy to make a mistake when controlling attribute access. Look at this example:

Python· Read with the text above
def __setattr__(self, name, value):
    self.name = value
    # Every time an attribute is assigned, __setattr__() is called, so this calls itself again (recursion).
    # It means self.__setattr__('name', value) runs, and each time the method calls itself. This will crash the program.

def __setattr__(self, name, value):
    # Store the value under the attribute name in the class's dictionary
    self.__dict__[name] = value  
    # Custom behaviour goes here

Here's an example that calls all of these methods:

Python· Runs on this page
Practise on the challenge page →
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __getattr__(self, name):
        print('__getattr__ was called')
        return super(User, self).__getattr__(name)

    def __setattr__(self, name, value):
        print('__setattr__ was called')
        return super(User, self).__setattr__(name, value)

    def __delattr__(self, name):
        print('__delattr__ was called')
        return super(User, self).__delattr__(name)

    def __getattribute__(self, name):
        print('__getattribute__ was called')
        return super(User, self).__getattribute__(name)


if __name__ == '__main__':
    user = User()
    # Setting an attribute calls __setattr__
    user.attr1 = True
    # The attribute exists, so only __getattribute__ is called
    user.attr1
    try:
        # The attribute doesn't exist: first __getattribute__, then __getattr__
        user.attr2
    except AttributeError:
        pass
    # __delattr__ is called
    del user.attr1

Output:

Text
__setattr__ was called
__getattribute__ was called
__getattribute__ was called
__getattr__ was called
__delattr__ was called

4. Descriptors

Generally speaking, a descriptor is an object attribute with "binding behaviour". Access to it is controlled by special descriptor methods.

These methods are __get__(), __set__() and __delete__().

An object that has these methods is called a descriptor.

By default, attributes are got, set and deleted using the object's dictionary (__dict__).

For example, to find a.x, Python looks in a.__dict__['x'] first, then type(a).__dict__['x'], then the parent classes of type(a) (not including metaclasses). If the value it finds is a descriptor, Python calls the descriptor's methods instead of doing the default thing.

Exactly where this happens in the search depends on which descriptor methods are defined.

Note: descriptors only work in new-style classes. We talked about new-style and old-style classes in an earlier section – have a look back if you're interested. The main feature of new-style classes is that every class inherits from type or object.

In object-oriented programming, if a class's attributes depend on each other, descriptors can help you organise the logic very neatly. In Django's ORM, fields like IntegerField in models.Model are built using descriptors.

Let's look at this example first:

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __init__(self, name='Two Drops', sex='Male'):
        self.sex = sex
        self.name = name

    def __get__(self, obj, objtype):
        print('Getting the name value')
        return self.name

    def __set__(self, obj, val):
        print('Setting the name value')
        self.name = val


class MyClass(object):
    x = User('Two Drops', 'Male')
    y = 5


if __name__ == '__main__':
    m = MyClass()
    print(m.x)

    print('\n')

    m.x = 'Three Drops'
    print(m.x)

    print('\n')

    print(m.x)

    print('\n')

    print(m.y)

Output:

Text
Getting the name value
Two Drops


Setting the name value
Getting the name value
Three Drops


Getting the name value
Three Drops


5

This example shows clearly when __get__() and __set__() are called.

Now let's look at a classic example.

We know distance can be measured in metres or in feet. Let's define a class to represent a distance, with two attributes: metres and feet.

Python· Runs on this page
Practise on the challenge page →
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-


class Meter(object):
    def __init__(self, value=0.0):
        self.value = float(value)

    def __get__(self, instance, owner):
        return self.value

    def __set__(self, instance, value):
        self.value = float(value)


class Foot(object):
    def __get__(self, instance, owner):
        return instance.meter * 3.2808

    def __set__(self, instance, value):
        instance.meter = float(value) / 3.2808


class Distance(object):
    meter = Meter()
    foot = Foot()


if __name__ == '__main__':
    d = Distance()
    print(d.meter, d.foot)
    d.meter = 1
    print(d.meter, d.foot)
    d.meter = 2
    print(d.meter, d.foot)

Output:

Text
0.0 0.0
1.0 3.2808
2.0 6.5616

In this example, before we assigned anything to the Distance instance, you might expect meter and foot to be objects of their own classes. But the output shows numbers. That's because __get__ is at work.

We only changed meter, giving it an int value – but foot changed too. That's __set__ at work.

Descriptor objects (Meter, Foot) can't live on their own. They need to be held by another owner class (Distance). A descriptor can reach the attributes of the instance that owns it, like instance.meter in Foot.

5. Custom Containers

From earlier chapters, we know Python's common container types are: dict, tuple, list and string. We also talked about mutable and immutable containers. Tuples and strings are immutable containers; dicts and lists are mutable containers.

The difference is that once an immutable container is created, you can't change any of its elements. For more details, look back at the earlier articles, which have pictures.

So here's a question: are these data structures enough for everything we need?

What if they're not – what if some special need can't be met with just these basic containers?

Then we need to make our own custom container. How do we do that?

Goal What you need
A custom immutable container type Define __len__ and __getitem__
A custom mutable container type On top of the immutable ones, also define __setitem__ and __delitem__
Your custom data type needs to be iterable Define __iter__
Return the length of your custom container Write __len__(self)
Your container can use self[key]. If key is the wrong type, raise TypeError. If there's no value for key, raise ValueError Write __getitem__(self, key)
When self[key] = value runs It calls __setitem__(self, key, value)
When del self[key] runs It actually calls __delitem__(self, key)
When you want your container to work with for x in container: or iter(container) Write __iter__(self), which returns an iterator

Let's use these magic methods to build a data structure from the Haskell language:

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class FunctionalList:
    ''' Works like the built-in list type, plus some extra methods: head, tail, init, last, drop, take'''

    def __init__(self, values=None):
        if values is None:
            self.values = []
        else:
            self.values = values

    def __len__(self):
        return len(self.values)

    def __getitem__(self, key):
        return self.values[key]

    def __setitem__(self, key, value):
        self.values[key] = value

    def __delitem__(self, key):
        del self.values[key]

    def __iter__(self):
        return iter(self.values)

    def __reversed__(self):
        return FunctionalList(reversed(self.values))

    def append(self, value):
        self.values.append(value)

    def head(self):
        # Get the first element
        return self.values[0]

    def tail(self):
        # Get everything after the first element
        return self.values[1:]

    def init(self):
        # Get everything before the last element
        return self.values[:-1]

    def last(self):
        # Get the last element
        return self.values[-1]

    def drop(self, n):
        # Get everything except the first n elements
        return self.values[n:]

    def take(self, n):
        # Get the first n elements
        return self.values[:n]

6. Magic Methods for Operators

There are really a lot of magic methods for operators, so we'll just list two groups:

1. Comparison Operators

Magic method What it does
__cmp__(self, other) If it returns a negative number, self < other; a positive number means self > other; 0 means self == other. Defining __cmp__ is strongly not recommended. Instead, define __lt__, __eq__ and so on separately. __cmp__ was removed in Python 3.
__eq__(self, other) Defines how == behaves
__ne__(self, other) Defines how != behaves
__lt__(self, other) Defines how < behaves
__gt__(self, other) Defines how > behaves
__le__(self, other) Defines how <= behaves
__ge__(self, other) Defines how >= behaves

A simple example makes it clear:

Look at the line labelled num1 != num2 below: inside the curly braces it actually still says num1 == num2, so the current code calls __eq__. To really test "not equal", change that expression to num1 != num2. Then __ne__ is called and you get True.

Python· Read with the text above
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class Number(object):
    def __init__(self, value):
        self.value = value

    def __eq__(self, other):
        print('__eq__')
        return self.value == other.value

    def __ne__(self, other):
        print('__ne__')
        return self.value != other.value

    def __lt__(self, other):
        print('__lt__')
        return self.value < other.value

    def __gt__(self, other):
        print('__gt__')
        return self.value > other.value

    def __le__(self, other):
        print('__le__')
        return self.value <= other.value

    def __ge__(self, other):
        print('__ge__')
        return self.value >= other.value


if __name__ == '__main__':
    num1 = Number(2)
    num2 = Number(3)
    print(f'num1 == num2 ? --------> {num1 == num2} \n')
    print(f'num1 != num2 ? --------> {num1 == num2} \n')
    print(f'num1 < num2 ? --------> {num1 < num2} \n')
    print(f'num1 > num2 ? --------> {num1 > num2} \n')
    print(f'num1 <= num2 ? --------> {num1 <= num2} \n')
    print(f'num1 >= num2 ? --------> {num1 >= num2} \n')

Output:

Text
__eq__
num1 == num2 ? --------> False

__eq__
num1 != num2 ? --------> False

__lt__
num1 < num2 ? --------> True

__gt__
num1 > num2 ? --------> False

__le__
num1 <= num2 ? --------> True

__ge__
num1 >= num2 ? --------> False

2. __str__ and __repr__: making print friendly

First, a problem. Let's write a very ordinary Book class:

Python· Read with the text above
class Book:
    def __init__(self, title):
        self.title = title

b = Book('Python Basics')
print(b)

What's the output?

Text
<__main__.Book object at 0x10a9f3d50>

A string of ✗ gibberish. By default, print(obj) calls object's __str__, which only tells you "this is a Book object at address 0x..." – useless information for a human.

1. __str__: a string for people

Let's override it:

Python· Runs on this page
Practise on the challenge page →
class Book:
    def __init__(self, title):
        self.title = title

    def __str__(self):
        return f'Book: {self.title}'

b = Book('Python Basics')
print(b)         # Book: Python Basics
print(str(b))    # Book: Python Basics

__str__ must return a string. Both print(obj) and str(obj) call it.

2. __repr__: a string for programmers

__repr__ also returns a string, but it's for something different: usually a way of writing the object that's for developers, ideally one that could recreate the object.

The classic cases are typing a variable's name straight into an interactive terminal, or putting objects in a list and printing it:

Python· Runs on this page
Practise on the challenge page →
class Book:
    def __init__(self, title):
        self.title = title

    def __str__(self):
        return f'Book: {self.title}'

    def __repr__(self):
        return f"Book(title={self.title!r})"

b = Book('Python Basics')
print(b)        # Book: Python Basics  ← uses __str__
print([b])      # [Book(title='Python Basics')]  ← inside a container, uses __repr__

Note:

  • If you only define __repr__ and not __str__, print(obj) falls back to __repr__
  • It doesn't work the other way round – if you only define __str__, [obj] still shows the default gibberish

Rule of thumb: write __repr__ first. Then think about whether to add a friendlier __str__.

5. __add__: letting objects use +

Python's + means different things for different types:

  • 1 + 2 → 3 (adding numbers)
  • 'a' + 'b' → 'ab' (joining strings)
  • [1] + [2] → [1, 2] (joining lists)

None of this is "hard-wired" into Python – each of these classes has its own __add__. We can make our own classes support + too.

2D vector addition with __add__

Python· Runs on this page
Practise on the challenge page →
class Vec2:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vec2(self.x + other.x, self.y + other.y)

    def __repr__(self):
        return f'Vec2({self.x}, {self.y})'

v1 = Vec2(1, 2)
v2 = Vec2(3, 4)
v3 = v1 + v2     # triggers v1.__add__(v2)
print(v3)        # Vec2(4, 6)

Note: __add__ usually returns a new object instead of changing self. It's the same reason 1 + 2 doesn't change 1.

The whole family of arithmetic operators

And there's more

There are lots of magic methods – this section only covers the most common ones to get you started. Look these up when you need them later:

Magic method When it's triggered
__call__ Lets an object be called like a function: obj()
__iter__ / __next__ Custom iterators
__enter__ / __exit__ Context managers for the with statement
__getattr__ / __setattr__ Intercepting attribute access
__new__ Controlling how an object is created (before __init__)

Summary of this section

  • Magic methods are special methods named like __name__, called by Python automatically
  • __str__ / __repr__: decide how an object becomes a string
  • __eq__ and friends: decide how comparisons work
  • __len__ / __getitem__: make an object behave like a container
  • __add__ and friends: let an object do arithmetic
