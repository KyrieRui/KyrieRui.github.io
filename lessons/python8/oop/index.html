1. The Ideas Behind Object-Oriented Programming

1. Two Basic Ideas of Object-Oriented Programming

In programming, there are usually two ways of thinking: procedure-oriented and object-oriented.

Procedure-oriented programming focuses on the steps to solve a problem.

It's like how we solve everyday problems: work out the steps, then do them one by one.

Object-oriented programming is a kind of abstraction. Abstraction means looking at the world by sorting things into groups.

Python is an object-oriented language.

If you've learned Java, you know Java's big idea is: everything is an object. Python is the same. When solving a real problem, you can break the problem down into separate objects.

Object-oriented programming has two basic ideas: classes and objects.

  • Class

A class describes a group of objects that have the same attributes (data) and methods (actions). It defines the attributes and methods that every object in the group shares. An object is an instance of a class.

  • Object

An instance of the data structure defined by a class.

2. The Three Main Features of Object-Oriented Programming

Object-oriented languages have three main features: inheritance, polymorphism and encapsulation.

  • Inheritance

A derived class (child class) inherits the fields and methods of a base class (parent class). Inheritance also lets you treat an object of the derived class as an object of the base class.

For example, a Dog object comes from the Animal class. This models an "is-a" relationship (a Dog is an Animal).

  • Polymorphism

It means doing the same action on different types of things, and they behave differently depending on their type (or class).

  • Encapsulation

"Encapsulation" means wrapping data and behaviour (actions) together into one whole thing – a class. Its purpose is to make things safer and programming simpler. People using the class don't need to know the details of how it works inside; they just use its members through its outside interface, with certain access permissions.

If this is your first time seeing an object-oriented language and you're totally confused right now, don't worry – that's normal. Below, we'll use lots of examples to learn Python's object-oriented features step by step.

2. Defining and Using a Class

1. How to Think About a Class

What is a class?

I think the simplest way to understand a class is this: a class is a bundle of variables and functions.

Look at this picture:

This picture explains a class nicely: it wraps variables and functions together.

Of course, we don't wrap things together for no reason. We put things that belong together into one class, so we can reuse them easily.

So by now, you've probably noticed that lots of programming ideas exist so we can be "lazy" and reuse things.

2. How to Define a Class

Now that we know what a class looks like, let's learn how to define one.

The syntax for defining a class:

Python· Syntax only
class ClassName():
    <statement-1>
    .
    .
    .
    <statement-N>

You can see we use the class statement to define our own class, just like we use the def statement to define a function.

Since a class is a bundle of variables and methods, let's create one:

Python· Read with the text above
class ClassA():
    var1 = 100
    var2 = 0.01
    var3 = 'Two Drops'

    def fun1():
        print('I am fun1')

    def fun2():
        print('I am fun1')

    def fun3():
        print('I am fun1')

See? We've defined a class called ClassA. The variables inside a class are called attributes, so this class has 3 attributes: var1, var2 and var3. It also has 3 class methods: fun1(), fun2() and fun3().

3. How to Use Class Attributes and Class Methods

Once we've defined a class, how do we use the attributes and methods inside it?

Here's how:

Using class attributes and methods

  • A variable inside a class is called an [attribute] – use it like this: Class.variable
  • A function inside a class is called a [method] – use it like this: Class.function()

3. Class Methods

1. How a Class Method Uses Class Attributes

We now know how to define a class. Here we'll see how a class method uses the class attributes in the same class.

Let's go straight to an example:

Python· Runs on this page
class ClassA():
    var1 = 'Two Drops'

    @classmethod
    def fun1(cls):
        print('I am fun1 ' + cls.var1)


ClassA.fun1()

Output:

Text
I am fun1 Two Drops

Notice there's an extra @classmethod above the method. What's that for?

It says the function below it is a class method. The name makes it easy to understand:

"class" is class, and "method" is method.

Do we really have to write this?

Yes, we do.

If you leave it out, you'll get an error.

Python· Read with the text above
class ClassA():
    var1 = 'Two Drops'

    def fun1(cls):
        print('I am fun1 ' + cls.var1)


ClassA.fun1()

The error:

Text
Traceback (most recent call last):
  File "/Users/twowater/dev/python/test/com/twowater/test.py", line 10, in <module>
    ClassA.fun1()
TypeError: fun1() missing 1 required positional argument: 'cls'

If you don't declare it as a class method, cls isn't passed in, and you can't use cls to get the class attributes.

So for a class method to use class attributes, you need to:

  • Put @classmethod above the method to declare it as a class method. Only then can it use class attributes.
  • Write cls as the first parameter. cls is short for "class". It means the class itself is passed in as an argument, so the method can use the class attributes.
  • Use class attributes like this: cls.variable_name

Remember: you can't leave out @classmethod or cls.

Leave either one out and you'll get an error.

2. Passing Arguments to Class Methods

We've learned how a class method uses class attributes. How do we pass arguments to a class method?

It's simple – just like a normal function, add more parameters.

Here's an example:

Python· Runs on this page
class ClassA():
    var1 = 'Two Drops'

    @classmethod
    def fun1(cls, age):  # Added an age parameter
        print('I am fun1 ' + cls.var1)
        print('Age: ' + str(age))


ClassA.fun1(18)  # Passing an extra argument

Output:

Text
I am fun1 Two Drops
Age: 18

5. Classes and Objects

1. How Classes and Objects Are Related

This part is about classes and objects. Let's start with how they're related.

A class is a template for objects.

We must have a class first before we can make objects.

A class is like a mould in a factory, and objects are the products made from the mould.

Going from mould to product is called instantiating the class.

After a class is instantiated, it becomes an object – like the product in our example.

2. Instantiating a Class

Note: instantiating a class looks different from using a class directly.

We learned before that using a class directly looks like this:

Python· Runs on this page
class ClassA():
    var1 = 'Two Drops'

    @classmethod
    def fun1(cls):
        print('var1 is: ' + cls.var1)


ClassA.fun1()

So what does instantiating a class look like?

Like this. Compare carefully – what's different between instantiating a class and using the class directly?

Python· Runs on this page
class ClassA(object):  # Don't worry about this for now; it's about inheritance, which comes later
    var1 = 'Two Drops'

    def fun1(self):  # No more @classmethod, and cls has become self
        print('var1 is: ' + self.var1)


# Instantiate it and use it
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)

Output:

Text
var1 is: Two Drops
Two Drops

The main differences are:

  • The method no longer has @classmethod – we don't declare it as a class method
  • The method's parameter cls has changed to self
  • To use the class, we first create an object with instance_name = Class() – this makes an instance of the class. Then we call methods with instance_name.function(), and use attributes with instance_name.variable_name.

Why did the parameter change from cls to self?

Actually, you don't have to write self. You can use any letter or name.

Let's try it:

Python· Runs on this page
class ClassA(object):
    var1 = 'Two Drops'

    def fun1(aaaaaaaa):  # self changed to aaaaaaaa
        print('var1 is: ' + aaaaaaaa.var1)


# Instantiate
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)

Output:

Text
var1 is: Two Drops
Two Drops

See? Changing self to aaaaaaaa still works the same.

Using cls and self is just our programming habit – it's the agreed style.

cls is short for "class" and means the class, while self means the object itself.

So when we instantiate an object, we use self.

And self is the special first parameter of every instance method.

One more idea to stress here: once you instantiate a class, the attributes and methods inside are no longer called class attributes and class methods. They're called instance attributes and instance methods (or object attributes and object methods).

Why stress this?

Because one class can make many instance objects.

Look at this example:

Python· Runs on this page
class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)


# Instantiate
b = ClassA()
# After instantiating, use its method
b.fun1()
# Or use its attribute
print(b.var1)

Output:

Text
var1 is: Two Drops
Two Drops
var1 is: Two Drops
Two Drops

I can use this one class to create object a and object b.

3. Instance Attributes and Class Attributes

One class can make many objects.

Using this picture, let's explore: how are instance attributes and class attributes related?

First question: if a class attribute changes, does the instance attribute change too?

As always, when we have a question, we test it with code.

Look at this program:

Python· Runs on this page
class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# Use its attribute
print(a.var1)

# Change the class attribute
ClassA.var1 = 'Three Drops'
# Print object a's attribute again
print(a.var1)

Output:

Text
Two Drops
Three Drops

From the result, when the class attribute changes, the instance attribute changes too.

That makes sense: the instance object is made from the class, so when the class attribute changes, the object's attribute changes too.

The other way round: if an instance attribute changes, does the class attribute change?

Of course not! Each instance is its own separate thing, and can't affect the class.

Let's test it:

Python· Runs on this page
class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# Use its attribute
print(a.var1)

# Change the instance's attribute
a.var1 = 'Three Drops'
# Print the instance's changed attribute
print(a.var1)

# Print the class's attribute
print(ClassA.var1)

Output:

Text
Two Drops
Three Drops
Two Drops

You can see that no matter how an instance changes its attribute, the class attribute isn't affected.

4. Instance Methods and Class Methods

Now let's ask the same question as above.

If a class method changes, does the instance method change too?

Look at this example:

Python· Runs on this page
class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('This is the original method')


# Instantiate
a = ClassA()
# Use its method
a.fun1()


# Change the class method
# 1. First, define a new function
def newFun1(self):
    print('This is the new method that replaced it')


# 2. Replace the old function with the new one – this is "overriding the class method"
ClassA.fun1 = newFun1

# Call the instance's method again
a.fun1()

Output:

Text
This is the original method
This is the new method that replaced it

I suggest you look at my examples carefully and type them out again yourself. Think about why we're doing this and what it proves.

Again: think a lot, type a lot.

Back to the point: from the result, when a class method changes, the instance method changes too.

In this example, to change the class method, we overrode it.

We used Class.original_function = new_function to override it.

Note: this assignment replaces the method; it doesn't call the function. So you can't add brackets. Class.original_function() = new_function() is wrong.

So if an instance method changes, does the class method change?

To test this, we'd need to override the instance method, then check whether the class method changed.

But we can't override an instance method this way.

See – it gives an error straight away.

    print('This is the new method that replaced it')

Where is each record stored?

We've covered classes and objects. Now let's turn study time into a very small class. First, find which data belongs to each record, and which description can be shared by the whole class.

Python· Runs on this page
class StudyRecord:
    category = 'Study record'

    def __init__(self, subject):
        self.subject = subject
        self.minutes = 0

    def add(self, minutes):
        self.minutes = self.minutes + minutes

    @classmethod
    def get_category(cls):
        return cls.category


python_record = StudyRecord('Python')
reading_record = StudyRecord('Reading')
python_record.add(15)
print(python_record.minutes)
print(reading_record.minutes)
print(StudyRecord.get_category())

Output:

Text
15
0
Study record

self.minutes is an attribute that belongs to each instance, so adding to the Python record doesn't change the Reading record. category is an attribute defined on the class, and here all the instances read it together.

You also need to tell apart the kinds of methods defined in a class: add(self, ...) here is an instance method, which receives the instance. get_category(cls) with @classmethod is a class method, which receives the class. self and cls are just agreed names, and not every method (instance, class and static methods) starts with self.

Try it yourself: add 5 minutes to each record. You should get 20 and 5. Then add a list of notes. Try writing self.notes = [] in __init__, and also try writing notes = [] on the class. Use append() and watch how shared data behaves differently. Names with double underscores mainly involve name mangling. They're not a permission system that blocks all outside access, so don't treat them as a safe way to keep secrets.

    6. The Initialisation Function
    

    1. What is the Initialisation Function?
    

    The initialisation function is a function that is called automatically when you create an instance.
    

    For example:
    

    Python· Runs on this page
    class ClassA(object):

    def __init__(self):
        print('Instance created')


# Instantiate
a = ClassA()
    

    Output (we didn't call the init method ourselves – it printed as soon as we created the instance):
    

    Text
    Instance created
    

    When the code runs a = ClassA(), it automatically calls the __init__(self) function.
    

    This __init__(self) function is the initialisation function, also called the constructor.
    

    The initialisation function always has the same form: init in the middle, meaning "initialise", with two underscores before and after. Inside the brackets of __init__(), the first parameter must be self, or you'll get an error.
    

    The constructor (initialisation function) looks like this:
    

    Python· Syntax only
    def __init__(self,[...):
    

    The initialisation function can take arguments too. For example:
    

    Python· Runs on this page
    class ClassA(object):

    def __init__(self, str):
        print('Instance created')
        print(str)


# Instantiate
a = ClassA('Hello, I am a new object!')
    

    Output:
    

    Text
    Instance created
Hello, I am a new object!
    

    2. The Destructor
    

    Since the constructor is called when an object is created, it makes sense that when an object is destroyed, the destructor is called.
    

    The destructor's syntax:
    

    Python· Syntax only
    def __del__(self,[...):
    

    Here's an example:
    

    Python· Runs on this page
    class ClassA(object):

    def __init__(self):
        print('Instance created')

    def __del__(self):
        print('Instance destroyed')


a = ClassA()
del a  # This destroys the object
    

    Output:
    

    Text
    Instance created
Instance destroyed

      7. Inheritance
      

      1. Defining Inheritance
      

      When you hear "inheritance", you probably think of inheriting money or a house from your parents.
      

      Class inheritance is similar.
      

      Say there's an old class that can work out averages. Now there's a new class that also needs to work out averages. We can use inheritance: the new class inherits from the old class, and then the new class has that ability too.
      

      Usually, we call the old class the parent class and the new class the child class.
      

      First, let's look at the basic syntax of inheritance:
      

      Python· Syntax only
      class ClassName(BaseClassName):
    <statement-1>
    .
    .
    .
    <statement-N>
      

      When you define a class, you put the class it inherits from in the brackets. If you're not inheriting from anything, you can still write object, because in Python object is the parent of every class.
      

      The example above is single inheritance. Python also supports multiple inheritance. The syntax is:
      

      Python· Syntax only
      class ClassName(Base1,Base2,Base3):
    <statement-1>
    .
    .
    .
    <statement-N>
      

      One thing to note with multiple inheritance: if the parent classes have methods with the same name, and the child class doesn't say which one to use, Python searches the parent classes from left to right, in the order they're written in the brackets. That is, if a method isn't found in the child class, Python looks for it in the parent classes from left to right.
      

      So what can a child class do?
      

      Benefits of a child class:
* It inherits the parent class's attributes and methods
* It can define its own, and override the parent's attributes and methods
      

      2. Calling the Parent Class's Methods
      

      Once a class inherits from a parent, it can call the parent's methods directly. In the example below, UserInfo2 inherits from the parent class UserInfo, and can call the parent's get_account method directly.
      

      Python· Runs on this page
      #!/usr/bin/env python
# -*- coding: UTF-8 -*-

class UserInfo(object):
    lv = 5

    def __init__(self, name, age, account):
        self.name = name
        self._age = age
        self.__account = account

    def get_account(self):
        return self.__account


class UserInfo2(UserInfo):
    pass


if __name__ == '__main__':
    userInfo2 = UserInfo2('Two Drops', 23, 347073565);
    print(userInfo2.get_account())
      

      3. Overriding a Parent Class's Method
      

      Of course, a child class can also override (rewrite) a parent class's method.
      

      Example:
      

      Python· Read with the text above
      #!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class UserInfo(object):
    lv = 5

    def __init__(self, name, age, account):
        self.name = name
        self._age = age
        self.__account = account

    def get_account(self):
        return self.__account

    @classmethod
    def get_name(cls):
        return cls.lv

    @property
    def get_age(self):
        return self._age


class UserInfo2(UserInfo):
    def __init__(self, name, age, account, sex):
        super(UserInfo2, self).__init__(name, age, account)
        self.sex = sex;


if __name__ == '__main__':
    userInfo2 = UserInfo2('Two Drops', 23, 347073565, 'Male');
    # Print all attributes
    print(dir(userInfo2))
    # Print the attributes set in the constructor
    print(userInfo2.__dict__)
    print(UserInfo2.get_name())

      Here we've overridden the parent class's constructor.
      

      4. Checking the Type of a Child Class
      

      With class inheritance, sometimes we need to check what type a class is. How do we do that?
      

      We can use the isinstance() function.
      

      One example is enough to show how isinstance() works:
      

      Python· Runs on this page
      #!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User1(object):
    pass


class User2(User1):
    pass


class User3(User2):
    pass


if __name__ == '__main__':
    user1 = User1()
    user2 = User2()
    user3 = User3()
    # isinstance() tells us whether an object is a certain type
    print(isinstance(user3, User2))
    print(isinstance(user3, User1))
    print(isinstance(user3, User3))
    # isinstance() works on basic types too
    print(isinstance('Two Drops', str))
    print(isinstance(347073565, int))
    print(isinstance(347073565, str))
      

      Output:
      

      Text
      True
True
True
True
True
False
      

      You can see isinstance() not only tells us whether an object is a certain type – it also works on basic types.

        8. Polymorphism
        

        Polymorphism isn't hard to understand. It means doing the same action on different types of things, and they behave differently depending on their type (or class).
        

        In fact, we use polymorphism all the time. For example:
        

        Text
        >>> 1 + 2
3
>>> 'a' + 'b'
'ab'
        

        When we use + on two integers, we get their sum. When we use the same + on two strings, we get the strings joined together.
        

        In other words, different types of objects respond differently to the same message.
        

        Let's look at an example to understand polymorphism:
        

        Python· Runs on this page
        #!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __init__(self, name):
        self.name = name

    def printUser(self):
        print('Hello !' + self.name)


class UserVip(User):
    def printUser(self):
        print('Hello ! Dear VIP user: ' + self.name)


class UserGeneral(User):
    def printUser(self):
        print('Hello ! Dear user: ' + self.name)


def printUserInfo(user):
    user.printUser()


if __name__ == '__main__':
    userVip = UserVip('Two Drops')
    printUserInfo(userVip)
    userGeneral = UserGeneral('Shui Shui Shui')
    printUserInfo(userGeneral)
        

        Output:
        

        Text
        Hello ! Dear VIP user: Two Drops
Hello ! Dear user: Shui Shui Shui
        

        You can see userVip and userGeneral are two different objects. When we call printUserInfo on them, each one automatically uses the printUser method of its real type, and they respond differently. That's the magic of polymorphism.
        

        Remember: polymorphism comes from inheritance. Because of inheritance, objects of different classes can respond differently to the same message.

          9. Access Control in Classes
          

          1. Access Control for Class Attributes
          

          In Java, there are public attributes and private attributes, which control who can access them.
          

          So does Python have access control for attributes?
          

          Usually, we start an attribute name with two underscores, like __private_attrs, to say it's private and shouldn't be used or accessed directly from outside the class. Inside the class's methods, you use it as self.__private_attrs.
          

          Why do we say "usually"?
          

          Because Python doesn't actually have real private attributes.
          

          In Python, access control depends on programmers choosing to follow the rules. Why do we say that?
          

          Look at this example:
          

          Python· Read with the text above
          class UserInfo(object):
    def __init__(self, name, age, account):
        self.name = name        # Anyone can access this
        self._age = age         # "Private" by convention, but we can still access it if we want. This isn't a Python syntax rule – it's just a coding convention
        self.__account = account  # With two underscores, you can't access it directly by this name from outside. But it's still not truly private – there's still a way to get at it
          

          Look carefully – why isn't the double-underscore attribute truly private? Let's test it with this example:
          

          Python· Read with the text above
          
#!/usr/bin/env python
# -*- coding: UTF-8 -*-

class UserInfo(object):
    def __init__(self, name, age, account):
        self.name = name
        self._age = age
        self.__account = account

    def get_account(self):
        return self.__account


if __name__ == '__main__':
    userInfo = UserInfo('Two Drops', 23, 347073565);
    # Print all attributes
    print(dir(userInfo))
    # Print the attributes set in the constructor
    print(userInfo.__dict__)
    print(userInfo.get_account())
    # Test whether the double-underscore attribute is really private
    print(userInfo._UserInfo__account)
          

          Output:
          

          Text
          ['_UserInfo__account', '__class__', '__delattr__', '__dict__', '__dir__', '__doc__', '__eq__', '__format__', '__ge__', '__getattribute__', '__gt__', '__hash__', '__init__', '__init_subclass__', '__le__', '__lt__', ...]
{'name': 'Two Drops', '_age': 23, '_UserInfo__account': 347073565}
347073565
347073565
          

          Looking at all the attributes and the ones set in the constructor, we defined an attribute called __account, but in the printout its name has been changed to _UserInfo__account. And the last line prints the double-underscore attribute directly, which proves it's not really private.
