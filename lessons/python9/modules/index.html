1. What is a Python Module?

As you write more and more code, a single file gets longer and longer, and harder and harder to look after.

Then we learned functions. A function is a piece of code that does one or more jobs, which makes it easier to reuse code.

After that, we learned classes. A class can wrap up methods and variables (attributes) together, which makes code even easier to look after.

We learned before that a class looks like this:

And the module we're learning now looks like this:

In a module, we can store variables directly, and also functions, and also classes.

Do you remember? We wrap up a function with def, and a class with class.

But to make a module, we don't need any statement at all.

In Python, one .py file is called a module.

Look at an example I wrote earlier in PyCharm. A test.py file like this is a module:

Text
test ~/dev/python/test
├── com
│   └── twowater
│       ├── __init__.py
│       ├── iter.py
│       └── test.py        ← This is a module
│   └── __init__.py
└── venv

# What's inside test.py:
#!/usr/bin/env python
# -*- coding: UTF-8 -*-

A module is really an extension of what functions do. Why do we say that?

Because a module is a block of code that does one or more jobs.

From this, it's easy to see that functions and modules are both for doing jobs. A module is just bigger than a function – a module can hold many functions.

But if we already have functions, why do we need modules?

The biggest benefit is that they make code much easier to look after.

Also, you don't have to write code from scratch. Once a module is written, it can be used anywhere else. When we write programs, we often use other modules, including Python's built-in modules and modules from other people (third-party modules).

Modules also help avoid name clashes between functions and variables. Functions and variables with the same name can live in different modules without any problem. So when we write our own modules, we don't have to worry about names clashing with other modules. But be careful not to clash with the names of built-in functions.

Python comes with lots of really useful built-in modules. Once Python is installed, you can use them straight away. Let's try to find them. 2. Using Modules

1. import

Using modules in Python is similar to other languages. To use a module, you must import it first. We import a module with the keyword import.

The basic syntax of import:

Python· Syntax only
import module1[, module2[,... moduleN]

For example, let's use the math module from the standard library. When the interpreter sees an import statement, and the module is in the current search path, it gets imported.

Python· Runs on this page
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import math

_author_ = 'Two Drops'

print(math.pi)

Output:

Text
3.141592653589793

A module is only imported once, no matter how many times you run import. This stops the module from running again and again.

When we use import, how does the Python interpreter find the right file?

This involves Python's search path. The search path is a list of folders, and the Python interpreter looks for the module in each folder in turn. It's a lot like an environment variable – in fact, you can set the search path with an environment variable. The search path is decided when Python is built or installed, and installing new libraries may also change it. It's stored in the path variable of the sys module.

So we can look at the path:

Python· Run it on your own computer
#!/usr/bin/env python
# -*- coding: UTF-8 -*-

import sys

print(sys.path)

Output:

Text
['C:\\Users\\Administrator\\Desktop\\Python\\Python8Code', 'G:\\PyCharm 2017.1.4\\helpers\\pycharm', 'C:\\Users\\Administrator\\AppData\\Local\\Programs\\Python\\Python36\\python36.zip', 'C:\\Users\\Administrator\\AppData\\Local\\Programs\\Python\\Python36\\DLLs', 'C:\\Users\\Administrator\\AppData\\Local\\Programs\\Python\\Python36\\lib', 'C:\\Users\\Administrator\\AppData\\Local\\Programs\\Python\\Python36', 'C:\\Users\\Administrator\\AppData\\Local\\Programs\\Python\\Python36\\lib\\site-packages', 'C:\\Users\\Administrator\\Desktop\\Python\\Python8Code\\com\\Learn\\module\\sys']

2. from···import

Have you wondered how to import a specific attribute or method from a module directly?

In Python, we use the import keyword to import a module. Note: this only imports the module – it doesn't import any specific attribute or method from inside it. If we want to import one specific thing from a module (an attribute or method) directly, we can use the from···import statement.

The syntax:

Python· Syntax only
from modname import name1[, name2[, ... nameN]]

After reading this, you might wonder: what's the difference between from···import and import?

To find out, look at these two examples:

Use import to import the sys module, then use its version attribute:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import sys

print(sys.version)   # Use the imported sys module to get its methods or attributes
print(version)       # Error! You can't use version directly, because only the sys module was imported

Result:

Text
3.6.1 (v3.6.1:69c0db5, Mar 21 2017, 18:41:36) [MSC v.1900 64 bit (AMD64)]
NameError: name 'version' is not defined

Use from···import to import the version attribute directly:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

from sys import version

print(version)   # Use version directly – no need for the sys. prefix

Result:

Text
3.6.1 (v3.6.1:69c0db5, Mar 21 2017, 18:41:36) [MSC v.1900 64 bit (AMD64)]

3. from ··· import *

From the above, we know from sys import version imports the version attribute directly.

But what if we want to use other attributes too?

For example, executable from the sys module. Do we have to write another line, from sys import executable? Two is OK, but what about three, or four?

Do we just keep writing more and more lines?

That's when you use from ··· import *. This statement imports all the methods and attributes from a module. For example:

Python· Run it on your own computer
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

from sys import *

print(version)
print(executable)

Output:

Text
3.6.1 (v3.6.1:69c0db5, Mar 21 2017, 18:41:36) [MSC v.1900 64 bit (AMD64)]
C:\Users\Administrator\AppData\Local\Programs\Python\Python36\python.exe

Note: this gives you a simple way to import everything from a module. But you shouldn't use it too much.

Learning to use a module you don't know

You don't need to memorise modules one by one. First, be clear about what you need right now: round a number up. We look in the standard library docs and find math.ceil. We check what it takes in and what it gives back, and then test it with very small inputs.

Python· Runs on this page
from math import ceil

print(ceil(2.1))
print(ceil(0))
print(ceil(-2.1))

Output:

Text
3
0
-2

The negative number result is worth stopping to think about: rounding up doesn't mean making the number's size bigger. After reading a function's description, checking it with a positive number, zero and a negative number helps you spot misunderstandings much better than trying just one positive number.

Later, in the final project, we'll put functions into tracker.py, and a test file will import them. Importing a module and running a script directly have different purposes. if __name__ == '__main__' lets the command-line entry point start only when the file is run directly. That way, when a test imports the file, it won't ask for command-line input.

If an import fails, first write down which Python is actually running, the current folder, the file name and the full error. Remove the unrelated code and keep only that one import to test. Also, don't name your own files things like math.py or json.py – they might hide the module you actually wanted to import.

      3. Main Modules and Non-Main Modules
      

      1. What Main and Non-Main Modules Are
      

      With Python functions, if a function calls other functions to do a job, we call it a main function. If a function doesn't call other functions, we call it a non-main function. Main and non-main modules are similar: if a module is run directly and not used by anyone else, we call it the main module. If a module is imported by another one, we call it a non-main module.
      

      2. The name Attribute
      

      Python has main modules and non-main modules, so of course we need a way to tell them apart. How?
      

      We use the __name__ attribute. __name__ is a variable that Python sets for us. We can use it to check whether a module is the main module. If its value is '__main__', then this module is the main module, and if not, it isn't. But note: __name__ being '__main__' only helps us CHECK whether it's the main module. It doesn't DECIDE whether it's the main module. What decides it is only whether the module was imported by someone else.
      

      Let's look at an example:
      

      First we create a module called lname, and check whether it's the main module. If it is, print main; if not, print not main. When we run this module directly, it's being used directly and not imported by anyone, so it's the main module, and it prints main:
      

      The code in com/Learn/module/nameattributes/lname.py:
      

      Python· Runs on this page
      #!/usr/bin/env python
# -*- coding: UTF-8 -*-

if __name__ == '__main__':
    print('main')
else:
    print('not main')
      

      Run lname.py directly. Output:
      

      Text
      main
      

      Then we create another module, user_lname, which simply imports the lname module. When we run it, the output is not main, because lname was imported by this module, so it's not the main module:
      

      The code in com/Learn/module/nameattributes/user_lname.py:
      

      Python· Read with the text above
      #!/usr/bin/env python
# -*- coding: UTF-8 -*-

import lname   # Import the lname module
      

      Run user_lname.py. Output:
      

      Text
      not main

      4. Packages
      

      We've actually already created different package names in some of the examples above – look closely and you'll see.
      

      At the start of the modules introduction, we said modules help avoid name clashes between functions and variables.
      

      Functions and variables with the same name can live in different modules without any problem. So when we write our own modules, we don't have to worry about names clashing with other modules. But be careful not to clash with the names of built-in functions.
      

      But there's still a problem: what if different people write modules with the same module name?
      

      To avoid module name clashes, Python lets you organise modules into folders. This is called a package.
      

      The first example used packages. That way, even if two modules have the same name, they won't clash, because their package names are different – in other words, their paths are different. As shown below, with the package names added, lname.py actually becomes com.Learn.module.nameattributes.lname.
      

      Text
      Python8Code
└── com
    └── Learn
        └── module
            └── nameattributes
                ├── __init__.py
                ├── lname.py        ← com.Learn.module.nameattributes.lname
                └── user_lname.py
            └── __init__.py
        └── __init__.py
    └── __init__.py
      

      If you look carefully, you'll notice every package folder has an __init__.py file. Why?
      

      Because this file is required. Without it, Python treats the folder as a normal folder, not a package. __init__.py can be an empty file, or it can have Python code in it, because __init__.py is itself a module, and its module name is the package name.

      5. Scope
      

      If you've learned Java, you know that in a Java class, methods and attributes can be public or private. This is because we want some functions and attributes to be used by others, and some to be used only inside.
      

      Modules in Python are a bit like classes in Java. So how do we make some functions and variables in a module available to others, and keep some only for use inside the module?
      

      In Python, we use a _ prefix. Normal function and variable names are public and can be used directly, like abc, ni12, PI and so on. Names like __xxx__ are special variables. They can be used directly, but they have special purposes. For example, __name__ above is a special variable, and so is __author__, which shows who wrote the code.
      

      Note: don't usually use names like this for your own variables. Functions or variables like _xxx and __xxx are non-public (private) and shouldn't be used directly, like _abc, __abc and so on.
      

      We say "shouldn't", not "can't". Python has no way to completely stop you from accessing private functions or variables. But as a good coding habit, you shouldn't use private functions or variables from outside.
      

      For example:
      

      Python· Runs on this page
      #!/usr/bin/env python3
# -*- coding: UTF-8 -*-

def _diamond_vip(lv):
    print('Hello, dear Diamond member')
    vip_name = 'DiamondVIP' + str(lv)
    return vip_name


def _gold_vip(lv):
    print('Hello, dear Gold member')
    vip_name = 'GoldVIP' + str(lv)
    return vip_name


def vip_lv_name(lv):
    if lv == 1:
        print(_gold_vip(lv))
    elif lv == 2:
        print(_diamond_vip(lv))


vip_lv_name(2)
      

      Output:
      

      Text
      Hello, dear Diamond member
DiamondVIP2
      

      In this module, we make the vip_lv_name function public, and the inner logic is done in the private functions _diamond_vip and _gold_vip. Since that's internal logic, the caller doesn't need to care about those functions at all – they only need to call vip_lv_name. So using private names is a really useful way to wrap up and hide details in your code.
      

      Usually, any function that doesn't need to be used from outside should be private, and only functions that need to be used from outside should be public.

      5. A few commonly used standard library modules
      

      These standard library modules come up all the time in everyday programming. Let's meet them first – the exercises below use them too.
      

      1. math – maths functions
      

      Python· Runs on this page
      import math

print(math.pi)          # pi, 3.141592653589793
print(math.e)           # the constant e
print(math.sqrt(16))    # square root → 4.0
print(math.floor(3.7))  # round down → 3
print(math.ceil(3.2))   # round up → 4
      

      2. random – random numbers
      

      Python· Runs on this page
      import random

random.seed(42)              # fix the random seed so the results repeat
print(random.randint(1, 10)) # a random whole number from 1 to 10 (both included)
print(random.choice(['A', 'B', 'C']))  # pick one at random
      

      

      In the exercises we use random.seed(...) to fix the results – that way the output is stable when it's checked.
      

      

      3. datetime – dates and times
      

      Python· Runs on this page
      from datetime import date, datetime

d = date(2026, 1, 1)
print(d.year, d.month, d.day)  # 2026 1 1

now = datetime(2026, 1, 1, 12, 30, 0)
print(now)                     # 2026-01-01 12:30:00
      

      4. json – turning data into JSON
      

      Turn a Python dictionary / list into a JSON string:
      

      Python· Runs on this page
      import json

data = {'name': 'Alice', 'age': 18}
print(json.dumps(data))
      

      Output:
      

      Text
      {"name": "Alice", "age": 18}
      

      And the other way round – parse a JSON string back into a Python object:
      

      Python· Runs on this page
      import json

s = '{"name": "Alice", "age": 18}'
obj = json.loads(s)
print(obj['name'])   # Alice
