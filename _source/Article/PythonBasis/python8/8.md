# 8. Polymorphism #

**Polymorphism** isn't hard to understand. It means doing the same action on different types of things, and they behave differently depending on their type (or class).

In fact, we use polymorphism all the time. For example:

```
>>> 1 + 2
3
>>> 'a' + 'b'
'ab'
```

When we use `+` on two integers, we get their sum. When we use the same `+` on two strings, we get the strings joined together.

In other words, **different types of objects respond differently to the same message.**


Let's look at an example to understand polymorphism:


```python
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

class User(object):
    def __init__(self, name):
        self.name = name

    def printUser(self):
        print('Hello !' + self.name)


class UserVip(User):
    def printUser(self):
        print('Hello ! Dear VIP user: ' + self.name)


class UserGeneral(User):
    def printUser(self):
        print('Hello ! Dear user: ' + self.name)


def printUserInfo(user):
    user.printUser()


if __name__ == '__main__':
    userVip = UserVip('Two Drops')
    printUserInfo(userVip)
    userGeneral = UserGeneral('Shui Shui Shui')
    printUserInfo(userGeneral)

```

Output:

```txt
Hello ! Dear VIP user: Two Drops
Hello ! Dear user: Shui Shui Shui
```

You can see `userVip` and `userGeneral` are two different objects. When we call `printUserInfo` on them, each one automatically uses the `printUser` method of its **real** type, and they respond differently. That's the magic of polymorphism.

Remember: polymorphism comes **from** inheritance. Because of inheritance, objects of different classes can respond differently to the same message.
