# A First Look at Python Regular Expressions

A **regular expression** (regex) is a special sequence of characters used to check whether a string matches a pattern that we set.

Python added the `re` module in version 1.5. It provides Perl-style regular expression patterns, and gives Python the full power of regular expressions.

Let's get to know regular expressions step by step, with examples.

Say we want to check whether a string contains some character or characters. Usually we use built-in functions, like this:

```python
# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Check whether it contains the string "TwoDrops", using Python's built-in functions

print(f'Does it contain "TwoDrops"? {a.index("TwoDrops") > -1}')
print(f'Does it contain "TwoDrops"? {"TwoDrops" in a}')
```

Output:

```txt
Does it contain "TwoDrops"? True
Does it contain "TwoDrops"? True
```

So what if we use a regular expression?

As we said, Python gives us the `re` module for all regular expression features. Let's use one of its functions first:

<!-- skip-ci -->
```python
re.findall(pattern, string[, flags])
```

This function finds **all** the parts of the string that match the regular expression, and returns them as a list. Like this:

```python

import re

# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Regular expression

findall = re.findall('TwoDrops', a)
print(findall)

if len(findall) > 0:
    print('a contains the string "TwoDrops"')
else:
    print('a does not contain the string "TwoDrops"')

```

Output:

```txt
['TwoDrops']
a contains the string "TwoDrops"
```

From the output, it does the same job as the built-in functions. But I must stress: this example is only to help us understand regular expressions. Writing a regex like this is pointless. Why?

Because if a problem can be solved with Python's built-in functions, there's no need for a regular expression – it's just extra work. Also, the "regular expression" in this example is just a fixed string, not a **rule**. The soul of a regular expression is its **rules**, so this doesn't mean much.

So how do you write a regex rule? Don't rush – let's go step by step. Let's start simple: find all the **lowercase letters** in the string. The first argument of `findall` is the regex rule. `[a-z]` matches any lowercase letter. The second argument is just the string to search. Like this:

```python

import re

# Set a constant
a = 'TwoDrops|twowater|liangdianshui|GrassRootsCoder|ReadingWithU'

# Pick out all the lowercase English letters in a

re_findall = re.findall('[a-z]', a)

print(re_findall)

```

Output:

```txt
['w', 'o', 'r', 'o', 'p', 's', 't', 'w', 'o', 'w', 'a', 't', 'e', 'r', 'l', 'i', 'a', 'n', 'g', 'd', 'i', 'a', 'n', 's', 'h', 'u', 'i', 'r', 'a', 's', 's', 'o', 'o', 't', 's', 'o', 'd', 'e', 'r', 'e', 'a', 'd', 'i', 'n', 'g', 'i', 't', 'h']
```

Now we've got all the lowercase letters in the string.



## Prepare examples that should match AND examples that shouldn't

We've built up the rules step by step. Now let's make the requirement a bit narrower: a name must be made of one or more English letters. First prepare three inputs for it, then look at the results:

```python
import re

pattern = r'[A-Za-z]+'
for name in ['Python', 'Python20', '']:
    print(bool(re.fullmatch(pattern, name)))
```

Output:

```text
True
False
False
```

`fullmatch` requires the **whole** text to match the rule. If you used `search` instead, the `'Python'` inside `'Python20'` would be found – but that doesn't mean the whole name meets the requirement. First be clear whether you mean "contains a part that matches" or "the whole thing matches", then choose your function.

Now add `'python'`, `'Python!'` and `'Two Drops'` yourself. You should get `True`, `False`, `False`. The last one is `False` because of the space – our rule only allows English letters.

When you use `index()` to find a substring and it isn't there, it raises a `ValueError` – it does **not** return `-1` for you to compare. If you only want to check whether some plain text is there, `'target' in text` is more direct. The more complicated your rule, the more you need to keep some examples that should match, some that shouldn't, and some edge cases.
