# Quantifiers

Let's keep going deeper into regular expressions. This part is about **quantifiers** (how many times). Why do we need them? Think about it: if you want to match dozens or hundreds of characters, do you really want to write them one by one? That's why quantifiers exist.

The syntax of a quantifier is `{min,max}`. `min` and `max` are non-negative integers. If there's a comma but no `max`, there's no upper limit. If there's no comma and no `max`, it repeats exactly `min` times. For example, `\b[1-9][0-9]{3}\b` matches a number from 1000 to 9999 (`\b` means a word boundary), and `\b[1-9][0-9]{2,4}\b` matches a number from 100 to 99999.

Here's an example that matches English words of 4 to 7 letters in a string:

```Python
import re

a = 'java*&39android##@@python'

# Quantifiers

findall = re.findall('[a-z]{4,7}', a)
print(findall)
```

Output:

```txt
['java', 'android', 'python']
```

Note: there's a difference between **greedy** and **non-greedy** matching. Let's look at what they mean:


**Greedy mode**: it reads in the whole string at once. If it doesn't match, it spits out the rightmost character and tries again, until it finds a match or the string is empty. Its aim is to read **as many characters as possible**, so it returns as soon as it finds its first match.

**Lazy mode**: it starts from the left of the string and tries to match while reading as few characters as possible. If that fails, it reads one more character and tries again, and so on. When it finds a match, it returns it, then carries on matching until the end of the string.

The example above is greedy. How do we use non-greedy (lazy) mode instead?

To use non-greedy mode, add a `?`. Let's change the example:

```Python
import re

a = 'java*&39android##@@python'

# Greedy vs non-greedy

re_findall = re.findall('[a-z]{4,7}?', a)
print(re_findall)

```

Output:

```txt
['java', 'andr', 'pyth']
```

From the output, `android` only gave `andr`, and `python` only gave `pyth`, because we're using lazy mode here.

There are also some special characters that mean "how many", like:


> `?`: tells the engine to match the character before it 0 or 1 times
>
> `+`: tells the engine to match the character before it 1 or more times
>
> `*`: tells the engine to match the character before it 0 or more times


Putting it all together gives this table:

| Greedy | Lazy | Description                          |
| ------- | ------- | ----------------------------- |
| ?      | ??    | Zero or one time, same as {0,1}   |
| +       | +?     | One or more times, same as {1,}   |
| *       | *?     | Zero or more times, same as {0,} |
| {n}     | {n}?   | Exactly n times                 |
| {n,m}   | {n,m}? | At least n and at most m times        |
| {n,}    | {n,}?  | At least n times                 |
