# Multithreaded Programming #

After a thread is created, it doesn't stay in one state the whole time. Its states are roughly:

* **New** – just created
* **Runnable** – ready, waiting to be scheduled
* **Running** – running
* **Blocked** – stuck; this could be waiting, waiting for a lock, or sleeping
* **Dead** – finished

Threads have different states, and also different kinds. Roughly:

* Main thread
* Child threads
* Daemon threads (background threads)
* Foreground threads

Now that we know a bit about these, let's look at some code.

## 1. Creating Threads ##

Python has two modules for working with threads: `thread` and `threading`.

The first is a low-level module for more basic operations. It's not often used in normal application development.

So let's use `threading` for our example:

```python
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import time
import threading


class MyThread(threading.Thread):
    def run(self):
        for i in range(5):
            print(f'thread {self.name}, @number: {i}')
            time.sleep(1)


def main():
    print("Start main threading")

    # Create three threads
    threads = [MyThread() for i in range(3)]
    # Start the three threads
    for t in threads:
        t.start()

    print("End Main threading")


if __name__ == '__main__':
    main()

```

## 2. Joining Threads (the join method) ##

From the output above, we can see the child threads are still running after the main thread has ended. What if we want the main thread to **wait** for the child threads to finish before it exits?

That's when we use the `join` method.

Let's add some code to the example above:

```python
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import time
import threading


class MyThread(threading.Thread):
    def run(self):
        for i in range(5):
            print(f'thread {self.name}, @number: {i}')
            time.sleep(1)


def main():
    print("Start main threading")

    # Create three threads
    threads = [MyThread() for i in range(3)]
    # Start the three threads
    for t in threads:
        t.start()

    # Call join on each new thread, one after another
    for t in threads:
        t.join()

    print("End Main threading")


if __name__ == '__main__':
    main()

```


From the output, you can clearly see that, compared with the example above, the main thread waits until the child threads have finished before it ends.

## 3. Thread Synchronisation and Locks ##

When several threads load and use data, the data often gets **out of sync**. To fix this, we can put a **lock** on a resource: a thread must get the lock before it can use the resource.

The `threading` module gives us a `Lock`:

<!-- skip-ci -->
```python
lock = threading.Lock()
```

Get (acquire) the lock in a thread:

<!-- skip-ci -->
```python
lock.acquire()
```

When we're done, we must release the lock:

<!-- skip-ci -->
```python
lock.release()
```

To let the same thread ask for the same resource several times, Python has a **re-entrant lock** (`RLock`). Inside, an `RLock` keeps a `Lock` and a `counter` variable. The counter records how many times `acquire` was called, so the resource can be acquired many times. Only after a thread has released every `acquire` can other threads get the resource.

How do you create a re-entrant lock? Just one line:

<!-- skip-ci -->
```python
r_lock = threading.RLock()
```

## 4. Condition Variables ##

Locks can keep threads in sync, but in more complicated situations, we need to check some conditions around the lock.

Python provides the `Condition` object.

**With a Condition object, you can wait to process data until some event happens or some condition is met. Besides the `acquire` and `release` methods of a Lock, a Condition also has `wait` and `notify` methods.**

A thread first acquires the condition variable's lock. If the condition isn't met, the thread **waits**. If it is met, the thread runs, and can even **notify** other threads. Other threads that are waiting check the condition again when they get the notification.

You can think of it like this: different threads take turns acquiring the lock. If a thread's condition isn't met, it's put into a "waiting pool" (of the Lock or RLock), until another thread notifies it and it checks the condition again. Repeating this over and over solves complicated synchronisation problems.

![Condition variables](../../images/diagrams/condition-flow.svg)

This pattern is often used for the **producer–consumer** pattern. Look at this example of a buyer and seller shopping online:

```python
#!/usr/bin/env python3
# -*- coding: UTF-8 -*-

import threading, time


class Consumer(threading.Thread):
    def __init__(self, cond, name):
        # Set up
        super(Consumer, self).__init__()
        self.cond = cond
        self.name = name

    def run(self):
        # Make sure the Producer's code runs first
        time.sleep(1)
        self.cond.acquire()
        print(self.name + ': If I buy these two items together, can I get a discount?')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': I have placed the order. Please change the price.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Got it. My payment went through.')
        self.cond.notify()
        self.cond.release()
        print(self.name + ': Waiting for delivery')


class Producer(threading.Thread):
    def __init__(self, cond, name):
        super(Producer, self).__init__()
        self.cond = cond
        self.name = name

    def run(self):
        self.cond.acquire()
        # Release the lock and pause the thread here, until it's notified and gets the lock back
        self.cond.wait()
        print(self.name + ': Sure, go ahead and place the order.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Done, I have changed it.')
        self.cond.notify()
        self.cond.wait()
        print(self.name + ': Payment received. I will ship it right away.')
        self.cond.release()
        print(self.name + ': Shipping the items')


cond = threading.Condition()
consumer = Consumer(cond, 'Buyer (Two Drops)')
producer = Producer(cond, 'Seller (Three Drops)')
consumer.start()
producer.start()

```

Output:

```txt
Buyer (Two Drops): If I buy these two items together, can I get a discount?
Seller (Three Drops): Sure, go ahead and place the order.
Buyer (Two Drops): I have placed the order. Please change the price.
Seller (Three Drops): Done, I have changed it.
Buyer (Two Drops): Got it. My payment went through.
Buyer (Two Drops): Waiting for delivery
Seller (Three Drops): Payment received. I will ship it right away.
Seller (Three Drops): Shipping the items
```

## 5. Communication Between Threads ##

If a program has several threads, they'll need to talk to each other. So how do we safely pass information or data between threads?

Probably the safest way to send data from one thread to another is to use a queue from the `queue` library. Create a `Queue` object shared by the threads, and the threads use `put()` and `get()` to add items to the queue or take them out.

```python
# -*- coding: UTF-8 -*-
from queue import Queue
from threading import Thread


def write(q):
    # The thread that writes data
    for value in ['Two Drops', 'Three Drops', 'Four Drops']:
        print(f'Value written to the Queue: {value}')
        q.put(value)
    q.put(None)  # Put an "end" marker when finished


def read(q):
    # The thread that reads data
    while True:
        value = q.get(True)
        if value is None:  # Stop when we read the end marker
            break
        print(f'Value read from the Queue: {value}')


if __name__ == '__main__':
    q = Queue()
    t1 = Thread(target=write, args=(q,))
    t2 = Thread(target=read, args=(q,))
    t1.start()
    t2.start()
```

Output:

```txt
Value written to the Queue: Two Drops
Value written to the Queue: Three Drops
Value read from the Queue: Two Drops
Value written to the Queue: Four Drops
Value read from the Queue: Three Drops
Value read from the Queue: Four Drops
```

Python also has an `Event` object for communication between threads. It's a signal flag set by a thread. Other threads can wait until the signal is set.

The `Event` object gives a simple way for threads to communicate. It lets you set the signal, clear the signal, and wait.

* Setting the signal

Use the Event's `set()` method to set its internal signal flag to true. The Event object has an `isSet()` method to check the flag. After you call `set()`, `isSet()` returns true.

* Clearing the signal

Use the Event's `clear()` method to clear the internal signal flag (set it to false). After you call `clear()`, `isSet()` returns false.

* Waiting

The Event's `wait` method returns quickly only when the internal signal is true. When the flag is false, `wait` keeps waiting until it becomes true.

Example:

```python
# -*- coding: UTF-8 -*-

import threading


class mThread(threading.Thread):
    def __init__(self, threadname):
        threading.Thread.__init__(self, name=threadname)

    def run(self):
        # Use the global Event object
        global event
        # Check the Event's internal signal flag
        if event.isSet():
            event.clear()
            # Add a timeout as a safety net: checking isSet() and calling clear() is not one atomic step,
            # so two threads could both pass the check and both wait(), with only one set() to wake them
            event.wait(timeout=1)
            print(self.getName())
        else:
            print(self.getName())
            # Set the Event's internal signal flag
            event.set()

# Create an Event object
event = threading.Event()
# Set the Event's internal signal flag
event.set()
t1 = []
for i in range(10):
    t = mThread(str(i))
    # Build a list of threads
    t1.append(t)

for i in t1:
    # Run the threads
    i.start()

```


Output:

```txt
1
0
3
2
5
4
7
6
9
8
```


## 6. Background (Daemon) Threads ##

By default, when the main thread exits, child threads keep running even if they weren't joined. If you want the child threads to stop when the main thread exits, you need to make them **background (daemon) threads**. Python provides the `setDaemon` method for this.
