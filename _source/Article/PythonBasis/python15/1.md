There are already lots of articles online about Python **closures**. In this one, we'll understand closures by solving a real problem.


Here's the problem: we want to keep a running record of our study time, in minutes. For example, if I study for 2 minutes, it returns 2. Later, I study for 10 more minutes, so it returns 12. It keeps adding up the study time like this.


For this problem, most people would create a **global variable** to store the time, and a function to add each new study time. Usually it would look like this:

<!-- skip-ci -->
```Python
time = 0

def insert_time(min):
    time = time + min
    return  time

print(insert_time(2))
print(insert_time(10))
```

Think carefully – is there a problem here?

In fact, this gives an error in Python:

```
UnboundLocalError: local variable 'time' referenced before assignment
```

That's because in Python, if a function uses the same name as a global variable **and changes its value**, that name becomes a **local** variable inside the function. So the function tries to use it before it's been defined inside the function, and you get this error.

If you really do want to use the global variable and change it inside a function, how?

We can use the `global` keyword, like this:

```Python
time = 0


def insert_time(min):
    global  time
    time = time + min
    return  time

print(insert_time(2))
print(insert_time(10))
```

Output:

```
2
12
```

But this uses a global variable, and in real projects we try to avoid global variables whenever we can. Because any module or function can freely access a global variable, its value can become unpredictable. For example, programmer A changes the global variable `time`, and at the same time programmer B changes `time` too. If one of them makes a mistake, it's very hard to find and fix.


Global variables make functions and modules less reusable, because different functions and modules all depend on them. Global variables also make code harder to read – the reader might not realise a variable is global.

Is there a better way?

Let's solve it with a closure. Look at the code first:

```python
time = 0


def study_time(time):
    def insert_time(min):
        nonlocal  time
        time = time + min
        return time

    return insert_time


f = study_time(time)
print(f(2))
print(time)
print(f(10))
print(time)
```

Output:

```
2
0
12
0
```

The most obvious thing is that the global variable `time` never changes at all. This code uses the `nonlocal` keyword, which means "use the variable from the outer (non-global) function". So how does this code run, step by step? Look at the comments below:

```python
time = 0


def study_time(time):
    def insert_time(min):                # Define a function inside a function. It adds the time and returns the final value
        nonlocal time
        time = time + min
        return time

    return insert_time                   # The outer function study_time returns the insert_time function. In Python, functions are objects too, so you can return a function


f = study_time(time)                     # Call study_time. It returns the insert_time function, so f is really the insert_time object
print(f(2))
print(time)
print(f(10))                             # This is like calling insert_time(10)
print(time)
```


When an inner function can use variables from the outer function's local scope, we call this a **closure**. Put more simply: when a function is returned as an object and carries outer variables with it, it forms a closure.


Closures avoid global variables. They also let you connect a function with some data (an environment) it works on. Closures can make code more elegant. And **decorators**, which we'll see in the next article, are built on closures too.


Now there's a question: just because I say it's a closure, does that make it one? Is there a way to check that this function really is a closure?


Yes. Every function has a `__closure__` attribute. If the function is a closure, it returns a tuple of **cell** objects. A cell's `cell_contents` attribute is the variable stored in the closure.

Let's print it and see:

```Python
time = 0


def study_time(time):
    def insert_time(min):
        nonlocal  time
        time = time + min
        return time

    return insert_time


f = study_time(time)
print(f.__closure__)
print(f(2))
print(time)
print(f.__closure__[0].cell_contents)
print(f(10))
print(time)
print(f.__closure__[0].cell_contents)
```

Output:

```
(<cell at 0x0000000000410C48: int object at 0x000000001D6AB420>,)
2
0
2
12
0
12
```

From the output, the value is always stored in the closure's `cell_contents`. This is the biggest feature of closures: they **bind** the parent function's variables to the function defined inside it. Even after the parent function that made the closure has finished, the closure still exists.

Making a closure is a bit like a class (the parent function) making an instance (the closure). The difference: a parent function only runs when it's called, and its environment is freed when it finishes. A class is created when the file runs, and its scope usually lasts until the program ends. So for features you want to reuse, but that aren't big enough to be a class, a closure can use fewer resources than a class, and is lighter and more flexible.




## Two people recording study time – will their records get mixed up?

So far we've been recording one set of study time. What if one person studies Python and another reads books, and they both use the same `study_time`? Will their records get mixed up?

First, guess what the four prints below will show:

```python
def study_time(time):
    def insert_time(minutes):
        nonlocal time
        time = time + minutes
        return time

    return insert_time


python_time = study_time(0)
reading_time = study_time(0)
same_record = python_time

print(python_time(2))
print(same_record(10))
print(reading_time(5))
print(python_time(0))
```

Output:

```text
2
12
5
12
```

Let's go through them in the order they're called:

1. `study_time(0)` is called twice. Each time, it creates its **own** `time`, and returns an inner function that uses that variable.
2. `same_record = python_time` just makes another name point to the function we already have. It doesn't call `study_time` again, and doesn't create a new record.
3. `python_time(2)` adds to the first record, making it `2`. `same_record(10)` then adds to the **same** record, making it `12`.
4. `reading_time(5)` changes the second record, so it gives `5`.
5. Finally, adding `0` to the first record leaves it at `12`.

The same outer function can make several **separate** records. The same inner function can also be pointed to by several names. Keep these two things apart, and you won't mix up "making a new closure" with "calling a closure you already have".

Here's one more detail to add to the definition above: what really matters is that the inner function **uses the outer function's variables**. Returning the inner function is just how this example lets the outside keep using it – it's not a required step to form a closure. You can compare with [closure variable in the official glossary](https://docs.python.org/3.13/glossary.html#term-closure-variable).

## Returning a function vs calling a function – it's all in the brackets

Look again at `return insert_time` above. There are no brackets, so it hands the **function itself** to the caller. Only after getting it do we write `python_time(2)` to record some study.

What if we wrote `return insert_time(2)` instead? Then the outer function would call `insert_time` once straight away, and return the **number** it calculated. The caller would get a number, and then writing `python_time(2)` would fail, because you can't call a number like a function.

Also, `nonlocal` is needed here because of the **reassignment**: `time = time + minutes`. It's not something you have to write every time an inner function uses an outer variable. You don't need it just to **read** an outer variable. And if you're working with an outer list, just calling the list's `append()` isn't reassigning the variable either. When you're not sure, ask yourself: is this line pointing the name somewhere new, or changing the existing object?

## Make your own record with a starting value

This time, don't start from `0`. Create two records: `python_time = study_time(30)` and `reading_time = study_time(10)`.

Record, in order: Python `5` minutes, reading `2` minutes, Python `3` minutes. You should get `35`, `12`, `38`. Then create `another_name = python_time` and use it to add `2` minutes. The first record should become `40`.

First write down on paper (or in your notes) which record each step changes, then change the code and check. If your results are different, first check whether you accidentally called `study_time` again and started a brand-new record.

When you print `__closure__`, the memory addresses change from computer to computer – they don't have to match the example. What you should look at is the variable being kept and how it changes. When comparing how many resources closures and classes use, you need to look at the actual code and actually measure it – it's not a promise that every closure uses less than every class. This problem only needs to keep one running total, so a closure expresses it clearly.
