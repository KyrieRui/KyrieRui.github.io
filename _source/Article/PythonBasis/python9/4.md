# 4. Packages #

We've actually already created different package names in some of the examples above – look closely and you'll see.

At the start of the modules introduction, we said modules help avoid name clashes between functions and variables.

Functions and variables with the same name can live in different modules without any problem. So when we write our own modules, we don't have to worry about names clashing with other modules. But be careful not to clash with the names of built-in functions.

But there's still a problem: what if different people write modules with the **same module name**?

To avoid module name clashes, Python lets you organise modules into folders. This is called a **package**.

The first example used packages. That way, even if two modules have the same name, they won't clash, because their package names are different – in other words, their paths are different. As shown below, with the package names added, `lname.py` actually becomes `com.Learn.module.nameattributes.lname`.

```
Python8Code
└── com
    └── Learn
        └── module
            └── nameattributes
                ├── __init__.py
                ├── lname.py        ← com.Learn.module.nameattributes.lname
                └── user_lname.py
            └── __init__.py
        └── __init__.py
    └── __init__.py
```

If you look carefully, you'll notice every package folder has an `__init__.py` file. Why?

Because this file is required. Without it, Python treats the folder as a normal folder, not a package. `__init__.py` can be an empty file, or it can have Python code in it, because `__init__.py` is itself a module, and its module name is the package name.
