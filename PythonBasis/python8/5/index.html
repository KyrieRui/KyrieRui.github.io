    5. Classes and Objects¶

    1. How Classes and Objects Are Related¶

    This part is about classes and objects. Let's start with how they're related.

    A class is a template for objects.

    We must have a class first before we can make objects.

    A class is like a mould in a factory, and objects are the products made from the mould.

    Going from mould to product is called instantiating the class.

    After a class is instantiated, it becomes an object – like the product in our example.

    2. Instantiating a Class¶

    Note: instantiating a class looks different from using a class directly.

    We learned before that using a class directly looks like this:

    class ClassA():
    var1 = 'Two Drops'

    @classmethod
    def fun1(cls):
        print('var1 is: ' + cls.var1)


ClassA.fun1()

    So what does instantiating a class look like?

    Like this. Compare carefully – what's different between instantiating a class and using the class directly?

    class ClassA(object):  # Don't worry about this for now; it's about inheritance, which comes later
    var1 = 'Two Drops'

    def fun1(self):  # No more @classmethod, and cls has become self
        print('var1 is: ' + self.var1)


# Instantiate it and use it
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)

    Output:

    var1 is: Two Drops
Two Drops

    The main differences are:

    • The method no longer has @classmethod – we don't declare it as a class method
    • The method's parameter cls has changed to self
    • To use the class, we first create an object with instance_name = Class() – this makes an instance of the class. Then we call methods with instance_name.function(), and use attributes with instance_name.variable_name.

    Why did the parameter change from cls to self?

    Actually, you don't have to write self. You can use any letter or name.

    Let's try it:

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(aaaaaaaa):  # self changed to aaaaaaaa
        print('var1 is: ' + aaaaaaaa.var1)


# Instantiate
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)

    Output:

    var1 is: Two Drops
Two Drops

    See? Changing self to aaaaaaaa still works the same.

    Using cls and self is just our programming habit – it's the agreed style.

    cls is short for "class" and means the class, while self means the object itself.

    So when we instantiate an object, we use self.

    And self is the special first parameter of every instance method.

    One more idea to stress here: once you instantiate a class, the attributes and methods inside are no longer called class attributes and class methods. They're called instance attributes and instance methods (or object attributes and object methods).

    Why stress this?

    Because one class can make many instance objects.

    Look at this example:

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# After instantiating, use its method
a.fun1()
# Or use its attribute
print(a.var1)


# Instantiate
b = ClassA()
# After instantiating, use its method
b.fun1()
# Or use its attribute
print(b.var1)

    Output:

    var1 is: Two Drops
Two Drops
var1 is: Two Drops
Two Drops

    I can use this one class to create object a and object b.

    3. Instance Attributes and Class Attributes¶

    One class can make many objects.

    Using this picture, let's explore: how are instance attributes and class attributes related?

    First question: if a class attribute changes, does the instance attribute change too?

    As always, when we have a question, we test it with code.

    Look at this program:

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# Use its attribute
print(a.var1)

# Change the class attribute
ClassA.var1 = 'Three Drops'
# Print object a's attribute again
print(a.var1)

    Output:

    Two Drops
Three Drops

    From the result, when the class attribute changes, the instance attribute changes too.

    That makes sense: the instance object is made from the class, so when the class attribute changes, the object's attribute changes too.

    The other way round: if an instance attribute changes, does the class attribute change?

    Of course not! Each instance is its own separate thing, and can't affect the class.

    Let's test it:

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('var1 is: ' + self.var1)


# Instantiate
a = ClassA()
# Use its attribute
print(a.var1)

# Change the instance's attribute
a.var1 = 'Three Drops'
# Print the instance's changed attribute
print(a.var1)

# Print the class's attribute
print(ClassA.var1)

    Output:

    Two Drops
Three Drops
Two Drops

    You can see that no matter how an instance changes its attribute, the class attribute isn't affected.

    4. Instance Methods and Class Methods¶

    Now let's ask the same question as above.

    If a class method changes, does the instance method change too?

    Look at this example:

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('This is the original method')


# Instantiate
a = ClassA()
# Use its method
a.fun1()


# Change the class method
# 1. First, define a new function
def newFun1(self):
    print('This is the new method that replaced it')


# 2. Replace the old function with the new one – this is "overriding the class method"
ClassA.fun1 = newFun1

# Call the instance's method again
a.fun1()

    Output:

    This is the original method
This is the new method that replaced it

    I suggest you look at my examples carefully and type them out again yourself. Think about why we're doing this and what it proves.

    Again: think a lot, type a lot.

    Back to the point: from the result, when a class method changes, the instance method changes too.

    In this example, to change the class method, we overrode it.

    We used Class.original_function = new_function to override it.

    Note: this assignment replaces the method; it doesn't call the function. So you can't add brackets. Class.original_function() = new_function() is wrong.

    So if an instance method changes, does the class method change?

    To test this, we'd need to override the instance method, then check whether the class method changed.

    But we can't override an instance method this way.

    See – it gives an error straight away.

    class ClassA(object):
    var1 = 'Two Drops'

    def fun1(self):
        print('This is the original method')


# Instantiate
a = ClassA()
# Use its method
a.fun1()


# 1. First, define a new function
def newFun1(self):
    print('This is the new method that replaced it')


# 2. Replace the instance method with the new function
a.fun1 = newFun1

# Call the instance's method again
a.fun1()

    The error:

    This is the original method
Traceback (most recent call last):
  File "/Users/twowater/dev/python/test/com/twowater/test.py", line 24, in <module>
    a.fun1()
TypeError: newFun1() missing 1 required positional argument: 'self'

    Where is each record stored?¶

    We've covered classes and objects. Now let's turn study time into a very small class. First, find which data belongs to each record, and which description can be shared by the whole class.

    class StudyRecord:
    category = 'Study record'

    def __init__(self, subject):
        self.subject = subject
        self.minutes = 0

    def add(self, minutes):
        self.minutes = self.minutes + minutes

    @classmethod
    def get_category(cls):
        return cls.category


python_record = StudyRecord('Python')
reading_record = StudyRecord('Reading')
python_record.add(15)
print(python_record.minutes)
print(reading_record.minutes)
print(StudyRecord.get_category())

    Output:

    15
0
Study record

    self.minutes is an attribute that belongs to each instance, so adding to the Python record doesn't change the Reading record. category is an attribute defined on the class, and here all the instances read it together.

    You also need to tell apart the kinds of methods defined in a class: add(self, ...) here is an instance method, which receives the instance. get_category(cls) with @classmethod is a class method, which receives the class. self and cls are just agreed names, and not every method (instance, class and static methods) starts with self.

    Try it yourself: add 5 minutes to each record. You should get 20 and 5. Then add a list of notes. Try writing self.notes = [] in __init__, and also try writing notes = [] on the class. Use append() and watch how shared data behaves differently. Names with double underscores mainly involve name mangling. They're not a permission system that blocks all outside access, so don't treat them as a safe way to keep secrets.
